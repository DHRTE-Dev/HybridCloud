## 1. 디스크와 장치 관리 개요

### 디스크 장치 관리 과정

Linux에서 디스크를 사용하는 일반적인 관리 과정은 다음과 같다.

**디스크 장착 → 장치 인식 → 파티션 작업 → 파일시스템 작업 → 마운트 작업**

| 단계 | 설명 |
|---|---|
| **디스크 장착** | 시스템에 물리 또는 가상 디스크를 추가한다. |
| **장치 인식** | 커널과 `udev`가 새로운 장치를 인식하고 `/dev`에 장치 파일을 생성한다. |
| **파티션 작업** | 디스크를 하나 이상의 논리적인 영역으로 분할한다. |
| **파일시스템 작업** | 파티션에 XFS, ext4 등의 파일시스템을 생성한다. |
| **마운트 작업** | 파일시스템을 디렉터리 트리에 연결한다. |

### 디스크 종류

| 종류 | 설명 |
|---|---|
| **HDD** | 자기 디스크를 이용하는 저장장치이다. |
| **IDE/PATA** | 병렬 전송 방식의 오래된 저장장치 인터페이스이다. |
| **SATA** | 직렬 전송 방식의 저장장치 인터페이스이다. |
| **SCSI** | 안정성과 확장성이 높은 저장장치 인터페이스이다. |
| **SAS** | Serial Attached SCSI로, SCSI 계열의 직렬 인터페이스이다. |
| **SSD** | 반도체를 이용하여 데이터를 저장하며 기계적인 구동부가 없다. |
| **NVMe** | PCIe 기반으로 SSD와 같은 비휘발성 메모리 저장장치에 최적화된 프로토콜이다. |

### 물리적 디스크 구조

| 구성 요소 | 설명 |
|---|---|
| **Spindle** | 플래터를 회전시키는 축이다. |
| **Platter** | 데이터가 저장되는 원판이다. |
| **Head** | 플래터의 데이터를 읽고 쓰는 부분이다. |
| **Head Actuator Arm** | 헤드를 이동시키는 장치이다. |
| **Sector** | 디스크에서 데이터를 저장하는 기본적인 논리 단위이다. |
| **Track** | 플래터 표면에서 동심원 형태로 구성되는 데이터 영역이다. |
| **Cylinder** | 여러 플래터의 동일 위치에 있는 트랙을 묶은 개념이다. |

### 디스크 종류별 특징

| 종류 | 주요 특징 |
|---|---|
| **IDE/PATA** | 오래된 병렬 전송 인터페이스이며 일반적으로 현재 시스템에서는 사용 빈도가 낮다. |
| **SATA** | 일반적인 HDD와 SSD에서 널리 사용되는 직렬 인터페이스이다. SATA 세대에 따라 전송 속도가 다르다. |
| **SCSI** | 높은 안정성과 확장성을 제공하지만 일반적으로 비용이 높다. |
| **SAS** | 서버 및 엔터프라이즈 환경에서 사용하는 SCSI 계열 직렬 인터페이스이다. |
| **SSD** | 기계적인 지연이 없어 HDD보다 빠른 임의 접근 성능을 제공하며 소음과 전력 소비가 낮다. |
| **NVMe** | PCIe를 기반으로 하며 SATA/SAS 기반 SSD보다 높은 성능과 낮은 지연시간을 제공할 수 있다. |

### 디스크 장치 이름 체계

| 장치 종류 | 일반적인 장치 이름 | 설명 |
|---|---|---|
| **IDE/PATA** | `/dev/hda`, `/dev/hdb` | IDE 계열의 전통적인 장치 이름이다. |
| **SCSI/SATA/SAS** | `/dev/sda`, `/dev/sdb`, `/dev/sdc` | Linux에서 일반적인 블록 장치 이름이다. |
| **virtio-blk** | `/dev/vda`, `/dev/vdb` | 가상 머신에서 사용하는 반가상화 블록 장치이다. |
| **virtio-scsi** | `/dev/sda`, `/dev/sdb` | SCSI 계층을 사용하는 반가상화 장치이다. |
| **NVMe** | `/dev/nvme0n1`, `/dev/nvme0n2` | NVMe 컨트롤러와 네임스페이스를 기반으로 이름이 구성된다. |
| **SD/MMC/eMMC** | `/dev/mmcblk0` | SD/MMC/eMMC 계열 저장장치이다. |

**NVMe 장치 이름 구성**

`/dev/nvme0n1p1`

| 부분 | 의미 |
|---|---|
| `nvme0` | NVMe **컨트롤러 번호**이다. |
| `n1` | 해당 컨트롤러의 **네임스페이스 번호**이다. |
| `p1` | 해당 네임스페이스의 **파티션 번호**이다. |

### virtio-blk와 virtio-scsi

| 항목 | **virtio-blk** | **virtio-scsi** |
|---|---|---|
| 구조 | 단일 블록 장치 중심 | SCSI 계층 기반 |
| 장치 연결 | 디스크별 장치가 구성된다. | 하나의 컨트롤러에 여러 디스크를 연결할 수 있다. |
| 장점 | 구조가 단순하고 낮은 지연시간을 기대할 수 있다. | 다수의 디스크와 다양한 SCSI 기능을 지원한다. |
| 기능 | 기본적인 블록 I/O에 적합하다. | Hotplug, SCSI 명령, 다중 큐 등의 기능을 활용할 수 있다. |
| 적합한 환경 | 단순한 VM 스토리지 | 다수 디스크 또는 고급 스토리지 환경 |


## 2. 파티션의 이해

### 파티션의 개념

**파티션(Partition)**은 하나의 물리적 디스크를 여러 개의 논리적인 저장 영역으로 나누는 것이다.

파티션을 분리하면 운영체제 영역, 사용자 데이터 영역, 스왑 영역 등 용도에 따라 저장공간을 구분하여 관리할 수 있다.

### 파티션을 사용하는 이유

| 목적 | 설명 |
|---|---|
| **공간 제한** | 애플리케이션이나 사용자가 사용할 수 있는 저장공간을 제한할 수 있다. |
| **데이터 분리** | 운영체제 파일과 사용자 파일을 별도의 영역으로 구분할 수 있다. |
| **Swap 영역 분리** | 메모리 스왑을 위한 별도의 영역을 구성할 수 있다. |
| **관리 효율 향상** | 디스크 공간을 용도별로 분리하여 백업 및 진단 작업을 효율적으로 수행할 수 있다. |

### MBR 파티션 방식

**MBR(Master Boot Record)**은 전통적인 파티션 테이블 방식이다.

| 항목 | 내용 |
|---|---|
| 일반적인 펌웨어 환경 | **BIOS** |
| 기본 파티션 | 최대 **4개의 Primary Partition** |
| 확장 파티션 | Primary 영역 하나를 Extended Partition으로 사용할 수 있다. |
| 논리 파티션 | Extended Partition 내부에 생성한다. |
| 일반적인 번호 | Primary/Extended는 `1~4`, Logical은 일반적으로 `5`부터 시작한다. |
| 주소 지정 | 전통적으로 32비트 LBA 구조를 사용한다. |
| 용량 제한 | 일반적인 512-byte sector 기준 약 **2 TiB** |
| 주요 한계 | 파티션 수와 디스크 크기에 제약이 있다. |

### GPT 파티션 방식

**GPT(GUID Partition Table)**는 MBR의 제약을 개선한 파티션 테이블 방식이다.

| 항목 | 내용 |
|---|---|
| 일반적인 펌웨어 환경 | **UEFI** |
| 기본 파티션 | Linux 환경에서 일반적으로 **최대 128개** |
| 파티션 유형 | Primary/Extended/Logical 구분이 없는 구조이다. |
| 식별 방식 | GUID를 사용하여 디스크와 파티션을 식별한다. |
| 백업 정보 | GPT 헤더 및 파티션 테이블 정보를 디스크 양쪽에 유지한다. |
| 오류 검출 | 체크섬을 사용하여 GPT 데이터의 오류를 검출할 수 있다. |
| 주소 지정 | 64비트 LBA를 사용한다. |
| 이론적 용량 | 최대 **8 ZiB** 수준의 주소 공간을 지원한다. |

### MBR과 GPT 비교

| 항목 | **MBR** | **GPT** |
|---|---|---|
| 펌웨어 | BIOS 중심 | UEFI 중심 |
| 기본 파티션 수 | 최대 4개 | 일반적으로 최대 128개 |
| Extended Partition | 사용 | 사용하지 않음 |
| Logical Partition | 사용 | 사용하지 않음 |
| 디스크 크기 | 약 2 TiB 제한 | 매우 큰 디스크 지원 |
| 파티션 식별 | 파티션 테이블 기반 | GUID 기반 |
| 파티션 테이블 백업 | 제한적 | 주/보조 GPT 제공 |
| 오류 검출 | 제한적 | 체크섬 사용 |
| 권장 환경 | 레거시 시스템 | **신규 시스템 및 대용량 디스크** |

### 주 파티션·확장 파티션·논리 파티션

| 종류 | 설명 |
|---|---|
| **Primary Partition** | MBR에서 직접 생성할 수 있는 기본 파티션이다. 최대 4개까지 구성할 수 있다. |
| **Extended Partition** | MBR의 Primary Partition 개수 제한을 보완하기 위한 컨테이너 역할의 파티션이다. |
| **Logical Partition** | Extended Partition 내부에 생성되는 파티션이다. 일반적으로 5번부터 번호가 부여된다. |

**핵심 구조**

- `P1 + P2 + P3 + P4` → Primary 4개
- `P1 + P2 + P3 + E4(L5, L6, ...)` → Primary 3개 + Extended 1개
- `E1(L5, L6, L7, ...)` → Extended 1개 + Logical Partition 여러 개


## 3. 장치 인식(Device Reconfiguration)

### 새 디스크 추가 절차

새로운 디스크를 시스템에 추가한 후에는 운영체제가 해당 장치를 인식해야 한다.

| 단계 | 작업 |
|---|---|
| **1** | 시스템을 종료한다. |
| **2** | 새로운 디스크를 장착한다. |
| **3** | 시스템을 부팅한다. |
| **4** | 부팅 과정에서 `systemd-udevd`가 장치를 감지하고 필요한 장치 처리를 수행한다. |
| **5** | `/dev` 아래에 장치 파일이 생성되었는지 확인한다. |
| **6** | `lsblk` 등으로 디스크를 확인한다. |

### 장치 인식의 조건

새로운 장치가 정상적으로 인식되었는지 확인할 때는 다음 요소를 확인한다.

| 확인 항목 | 확인 방법 |
|---|---|
| **장치 장착 여부** | 물리적 또는 가상 장치 구성 확인 |
| **드라이버 로딩 여부** | `lsmod` 등을 이용하여 관련 모듈 확인 |
| **장치 파일 생성 여부** | `/dev` 아래의 장치 파일 확인 |
| **블록 장치 확인** | `lsblk`를 이용하여 확인 |

### 장치 확인 명령어

| 명령어 | 설명 |
|---|---|
| `lsblk` | 블록 장치의 계층 구조를 확인한다. |
| `lsblk -p` | 장치의 전체 경로를 표시한다. |
| `lsblk --fs` | 파일시스템 관련 정보를 함께 표시한다. |
| `lsblk --fs -p` | 전체 장치 경로와 파일시스템 정보를 함께 확인한다. |
| `ls -l /dev/nvme0*` | NVMe 관련 장치 파일을 확인한다. |
| `lsmod` | 현재 커널에 로드된 모듈을 확인한다. |
| `swapon -s` | 활성화된 Swap 영역을 확인한다. |
| `cat /proc/swaps` | Swap 상태를 `/proc` 인터페이스를 통해 확인한다. |
| `df -hT` | 파일시스템의 용량과 유형을 사람이 읽기 쉬운 형태로 확인한다. |
| `df -hT -t xfs` | XFS 파일시스템만 필터링하여 확인한다. |

### partprobe와 udevadm settle

파티션 테이블을 변경한 뒤 커널과 `/dev` 장치 노드에 변경 사항을 반영해야 할 수 있다.

| 명령어 | 역할 |
|---|---|
| **`partprobe`** | 변경된 파티션 테이블을 커널이 다시 읽도록 요청한다. |
| **`partprobe /dev/sdb`** | 지정한 디스크의 파티션 테이블을 다시 읽도록 요청한다. |
| **`udevadm settle`** | `udev` 이벤트 처리가 완료될 때까지 기다린다. |

### 장치 인식 과정 정리

**파티션 테이블 변경 → 커널 파티션 정보 갱신 → uevent 발생 → udev 이벤트 처리 → `/dev` 장치 노드 생성**

| 명령어 | 처리 단계 |
|---|---|
| `fdisk`, `parted`, `gdisk` | 파티션 테이블 변경 |
| `partprobe` | 커널이 변경된 파티션 정보를 다시 읽도록 요청 |
| `udevadm settle` | `udev` 이벤트 처리 완료 대기 |
| `lsblk`, `ls -l /dev/...` | 최종 결과 확인 |


## 4. 파티션 작업 도구

### fdisk

**fdisk**는 명령행 기반의 전통적인 파티션 관리 도구이다.

- 한 번에 하나의 디스크를 대상으로 작업한다.
- 파티션 생성, 삭제, 유형 변경 등의 작업을 수행할 수 있다.
- MBR 작업에 전통적으로 사용된다.
- 최신 util-linux의 `fdisk`는 GPT도 지원하므로, 자료의 "fdisk는 GPT를 지원하지 않는다"는 표현은 수정해야 한다.
- 대용량 디스크에서는 GPT를 사용하는 것이 일반적이다.

### gdisk

**gdisk(GPT fdisk)**는 GPT 파티션 테이블을 중심으로 작업하는 도구이다.

- `fdisk`와 유사한 대화형 인터페이스를 제공한다.
- GPT 파티션 작업에 적합하다.
- MBR 파티션을 GPT로 변환하거나 GPT 작업을 수행할 수 있다.
- 자료에서는 2 TiB 이상 디스크 작업 도구로 소개하고 있지만, 실제 선택 기준은 디스크 크기뿐 아니라 **파티션 테이블 형식(GPT)**을 기준으로 판단하는 것이 적절하다.

### parted

**parted**는 MBR과 GPT를 모두 지원하는 파티션 관리 도구이다.

- 대화형 및 비대화형 작업을 지원한다.
- 대용량 디스크 및 GPT 파티션 작업에 적합하다.
- 스크립트 방식의 자동화 작업에 사용할 수 있다.
- `mklabel`, `mkpart`, `print`, `rm`, `set` 등의 하위 명령어를 제공한다.
- 파티션 변경 사항은 일반적으로 명령 실행 시 바로 디스크에 반영되므로 주의해야 한다.

### 파티션 작업 도구 선택 기준

| 도구 | 주요 용도 | 파티션 형식 |
|---|---|---|
| **fdisk** | 전통적인 파티션 작업 및 명령행 관리 | MBR, GPT |
| **gdisk** | GPT 중심의 파티션 작업 | GPT |
| **parted** | MBR/GPT 및 자동화 작업 | MBR, GPT |

**권장 기준**

- 신규 시스템 → **GPT**
- NVMe 디스크 → 일반적으로 **GPT**
- 레거시 BIOS 호환이 필요한 경우 → 필요에 따라 **MBR**
- 대용량 디스크 → **GPT**
- 자동화된 파티션 작업 → **parted** 활용


## 5. fdisk를 이용한 파티션 작업

### fdisk 기본 형식

| 명령어 | 설명 |
|---|---|
| `fdisk /dev/sda` | 지정한 디스크의 파티션을 대화형으로 관리한다. |
| `fdisk /dev/nvme0n1` | 지정한 NVMe 디스크의 파티션을 관리한다. |
| `fdisk -l` | 모든 인식된 디스크의 파티션 정보를 출력한다. |
| `fdisk -l /dev/sda` | 특정 디스크의 파티션 정보를 출력한다. |

### fdisk 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-l` | 파티션 테이블을 출력한다. |
| `-v` | `fdisk` 버전을 출력하고 종료한다. |
| `-s` | 지정한 파티션의 크기를 블록 단위로 출력한다. |
| `-b sectorsize` | 섹터 크기를 지정한다. |

### fdisk 내부 명령어

| 명령 | 의미 | 설명 |
|---|---|---|
| **`m`** | menu | 도움말 메뉴를 표시한다. |
| **`p`** | print | 현재 파티션 테이블을 출력한다. |
| **`n`** | new | 새 파티션을 생성한다. |
| **`d`** | delete | 기존 파티션을 삭제한다. |
| **`t`** | type | 파티션 유형을 변경한다. |
| **`i`** | info | 파티션 상세 정보를 출력한다. |
| **`v`** | verify | 파티션 테이블을 검증한다. |
| **`F`** | free | 사용하지 않는 공간을 표시한다. |
| **`l`** | list | 사용 가능한 파티션 유형을 출력한다. |
| **`w`** | write | 변경 사항을 저장하고 종료한다. |
| **`q`** | quit | 변경 사항을 저장하지 않고 종료한다. |
| **`g`** | GPT | 새로운 GPT 파티션 테이블을 생성한다. |
| **`o`** | DOS/MBR | 새로운 MBR(DOS) 파티션 테이블을 생성한다. |

### 파티션 생성

`fdisk`에서 `n` 명령을 사용하여 새 파티션을 생성한다.

| 입력 항목 | 설명 |
|---|---|
| `n` | 새 파티션 생성 |
| `p` | Primary Partition 선택 |
| `e` | Extended Partition 선택 |
| 파티션 번호 | 생성할 파티션 번호 지정 |
| First sector | 시작 섹터 지정. 기본값을 사용하려면 `Enter` |
| Last sector | 종료 섹터 또는 `+500M`, `+1G`와 같은 크기 지정 |

### 확장 파티션과 논리 파티션 생성

MBR에서는 Primary Partition 4개 제한을 보완하기 위해 Extended Partition을 사용할 수 있다.

| 구성 | 의미 |
|---|---|
| `P1` | Primary Partition |
| `P2` | Primary Partition |
| `E3` | Extended Partition |
| `L5` | Extended Partition 내부의 Logical Partition |
| `L6` | Extended Partition 내부의 Logical Partition |

### 파티션 삭제

`fdisk`에서 **`d`**를 사용한다.

삭제 시에는 삭제할 파티션 번호를 지정한다.

파티션이 중첩된 구조라면 **Logical Partition → Extended Partition → Primary Partition** 순으로 정리하는 것이 안전하다.

### 파티션 유형 변경

`fdisk`의 **`t`** 명령으로 파티션의 유형을 변경할 수 있다.

| 명령 | 설명 |
|---|---|
| `t` | 파티션 유형 변경 |
| `l` | 사용 가능한 파티션 유형 목록 확인 |
| 파티션 번호 | 유형을 변경할 대상 파티션 |
| 유형 코드 | 지정한 파티션 유형으로 변경 |

### 파티션 변경 사항 반영

`fdisk`에서 변경 사항을 저장한 뒤 커널이 변경된 파티션 정보를 아직 인식하지 못할 수 있다.

일반적인 처리 순서는 다음과 같다.

**`fdisk` → `w` → `partprobe` → `udevadm settle` → `lsblk`**

### 자주 사용하는 fdisk 사용 예제

파티션 테이블 확인: `fdisk -l /dev/sda`

특정 디스크의 파티션 작업 시작: `fdisk /dev/sda`

현재 파티션 테이블 확인: `fdisk` 실행 후 `p`

새 파티션 생성: `fdisk` 실행 후 `n`

파티션 삭제: `fdisk` 실행 후 `d`

파티션 유형 변경: `fdisk` 실행 후 `t`

변경 사항 저장: `fdisk` 실행 후 `w`

저장하지 않고 종료: `fdisk` 실행 후 `q`

변경 사항 반영: `partprobe`

최종 장치 확인: `lsblk --fs -p`


## 6. gdisk를 이용한 GPT 파티션 작업

### gdisk 특징

**gdisk**는 GPT 파티션 테이블을 중심으로 사용하는 파티션 관리 도구이다.

| 특징 | 설명 |
|---|---|
| 기본 대상 | **GPT** |
| 인터페이스 | `fdisk`와 유사한 대화형 방식 |
| 용도 | GPT 파티션 생성, 삭제, 유형 변경 및 관리 |
| 장점 | GPT의 파티션 구조를 직접 관리하기 편리하다. |
| 변환 | 기존 MBR 파티션을 GPT 형식으로 변환하는 작업에도 활용할 수 있다. |

### gdisk 설치

자료에서는 다음 패키지를 설치하여 `gdisk`를 사용할 수 있도록 구성한다.

`dnf install -y epel-release`

`dnf install -y gdisk`

### gdisk 기본 형식

| 명령어 | 설명 |
|---|---|
| `gdisk -l /dev/sdb` | GPT 파티션 정보를 확인한다. |
| `gdisk /dev/sdb` | 지정한 디스크의 GPT 파티션을 대화형으로 관리한다. |

### GPT 파티션 유형 코드

| gdisk 코드 | 의미 | fdisk 계열 코드 |
|---|---|---|
| **`8200`** | Linux swap | `82` |
| **`8300`** | Linux filesystem | `83` |
| **`8e00`** | Linux LVM | `8e` |
| **`fd00`** | Linux RAID | `fd` |

### MBR과 GPT 변환

`gdisk`는 기존 MBR 파티션을 읽어 GPT 형식으로 변환할 수 있다.

변환 과정에서 기존 파티션을 그대로 유지할 수 있는 경우가 있지만, 실제 변환 작업에서는 **데이터 손실 가능성을 반드시 고려해야 한다.**

### 자주 사용하는 gdisk 사용 예제

GPT 파티션 정보 확인: `gdisk -l /dev/sdb`

GPT 파티션 작업 시작: `gdisk /dev/sdb`

MBR 디스크를 `gdisk`로 열면 기존 MBR 정보를 기반으로 GPT 변환 작업을 수행할 수 있다.

변경 사항을 저장하려면 `w`를 사용한다.


## 7. parted를 이용한 파티션 작업

### parted 특징

**parted**는 MBR과 GPT를 모두 지원하는 파티션 관리 도구이다.

| 특징 | 설명 |
|---|---|
| 파티션 형식 | **MBR 및 GPT** |
| 작업 방식 | 대화형 및 비대화형 |
| 대용량 디스크 | GPT 환경에 적합 |
| 자동화 | `-s` 옵션을 이용하여 스크립트 형태로 작업할 수 있다. |
| 주요 명령 | `help`, `print`, `mklabel`, `mkpart`, `rm`, `set`, `quit` |

### 대화형 작업과 비대화형 작업

| 방식 | 형식 | 설명 |
|---|---|---|
| **대화형** | `parted /dev/sdb` | `(parted)` 프롬프트에서 명령을 순차적으로 입력한다. |
| **비대화형** | `parted /dev/sdb print` | 하나의 명령을 직접 실행한다. |
| **스크립트** | `parted -s /dev/sdb ...` | 여러 작업을 자동으로 수행한다. |

### parted 도움말

| 명령어 | 설명 |
|---|---|
| `parted /dev/sdb help` | 전체 도움말을 확인한다. |
| `parted /dev/sdb help print` | `print` 사용법을 확인한다. |
| `parted /dev/sdb help mklabel` | `mklabel` 사용법을 확인한다. |
| `parted /dev/sdb help mkpart` | `mkpart` 사용법을 확인한다. |
| `(parted) help` | 대화형 모드의 도움말을 확인한다. |
| `(parted) help mkpart` | 대화형 모드에서 `mkpart` 도움말을 확인한다. |

### 파티션 테이블 생성

`mklabel`을 사용하여 파티션 테이블 형식을 지정한다.

| 명령어 | 설명 |
|---|---|
| `mklabel msdos` | MBR 파티션 테이블을 생성한다. |
| `mklabel gpt` | GPT 파티션 테이블을 생성한다. |

비대화형 방식에서는 다음과 같이 사용할 수 있다.

`parted /dev/sdb mklabel gpt`

`parted /dev/sdb mklabel msdos`

### parted 파티션 생성

`mkpart` 형식은 다음과 같다.

`mkpart <파티션종류> <파일시스템종류> <시작> <끝>`

| 요소 | 설명 |
|---|---|
| 파티션 종류 | `primary`, `extended`, `logical` |
| 파일시스템 종류 | `ext2`, `ext3`, `ext4`, `xfs` 등 |
| 시작 | 파티션 시작 위치 |
| 끝 | 파티션 종료 위치 |

GPT에서는 파티션을 Primary/Extended/Logical로 구분하지 않으므로 파티션 이름을 사용하는 방식으로 작업할 수 있다.

### parted 파티션 정보 확인

| 명령어 | 설명 |
|---|---|
| `parted /dev/sdb print` | 지정한 디스크의 파티션 테이블을 확인한다. |
| `(parted) print` | 대화형 모드에서 파티션 정보를 출력한다. |

### parted 파티션 삭제

| 명령어 | 설명 |
|---|---|
| `parted /dev/sdb rm 1` | 1번 파티션을 삭제한다. |
| `(parted) rm 1` | 대화형 모드에서 1번 파티션을 삭제한다. |

### 파티션 플래그 변경

`set` 명령으로 파티션 플래그를 변경할 수 있다.

| 명령어 | 설명 |
|---|---|
| `set 1 boot on` | 1번 파티션의 boot 플래그를 활성화한다. |
| `set 1 boot off` | boot 플래그를 비활성화한다. |
| `set 1 swap on` | swap 플래그를 활성화한다. |
| `set 1 lvm on` | LVM 플래그를 활성화한다. |
| `set 1 raid on` | RAID 플래그를 활성화한다. |

일반적인 형식은 다음과 같다.

`set NUMBER FLAG STATE`

| 항목 | 의미 |
|---|---|
| `NUMBER` | 파티션 번호 |
| `FLAG` | `boot`, `root`, `swap`, `raid`, `lvm` 등 |
| `STATE` | `on` 또는 `off` |

### 스크립트 방식 작업

`-s` 옵션을 이용하면 `parted`를 비대화형으로 실행할 수 있다.

MBR 예시 형식:

`parted -s /dev/sdb mklabel msdos mkpart primary 1MiB 200MiB`

GPT 예시 형식:

`parted -s /dev/sdb mklabel gpt mkpart primary 1MiB 200MiB`

스크립트 방식은 반복적인 파티션 구성을 자동화할 때 유용하다.

### 자주 사용하는 parted 사용 예제

파티션 정보 확인: `parted /dev/sdb print`

대화형 작업 시작: `parted /dev/sdb`

GPT 파티션 테이블 생성: `parted /dev/sdb mklabel gpt`

MBR 파티션 테이블 생성: `parted /dev/sdb mklabel msdos`

파티션 생성: `parted /dev/sdb mkpart primary xfs 2048s 100MB`

파티션 삭제: `parted /dev/sdb rm 1`

파티션 플래그 설정: `parted /dev/sdb set 1 lvm on`

대화형 모드 종료: `(parted) quit`

udev 처리 완료 대기: `udevadm settle`


## 8. 파티션 스키마 변경

### MBR에서 GPT로 변경

`parted`를 이용하면 파티션 테이블 형식을 직접 지정할 수 있다.

`parted /dev/sdb mklabel gpt`

`fdisk`에서는 대화형 모드에서 `g`를 사용하여 새로운 GPT 파티션 테이블을 생성할 수 있다.

`fdisk /dev/sdb`

`g`

`w`

**주의:** 새로운 파티션 테이블을 생성하면 기존 파티션 정보와 데이터에 영향을 줄 수 있으므로 실제 운영 디스크에서는 백업 및 영향도 검토가 필수이다.

### GPT에서 MBR로 변경

`parted`에서는 다음과 같이 지정한다.

`parted /dev/sdb mklabel msdos`

`fdisk`에서는 대화형 모드에서 `o`를 사용하여 새로운 DOS/MBR 파티션 테이블을 생성할 수 있다.

`fdisk /dev/sdb`

`o`

`w`

### 파티션 스키마 확인

| 명령어 | 설명 |
|---|---|
| `fdisk -l /dev/sdb` | 파티션 테이블 형식과 파티션 정보를 확인한다. |
| `gdisk -l /dev/sdb` | GPT 관점에서 파티션 정보를 확인한다. |
| `parted /dev/sdb print` | 파티션 테이블 형식과 파티션 정보를 확인한다. |
| `lsblk --fs -p` | 블록 장치 및 파일시스템 정보를 확인한다. |

### 스키마 변경 시 주의사항

**파티션 테이블 형식 변경은 데이터 손실 위험이 매우 크다.**

특히 다음 작업은 기존 파티션 정보를 제거할 수 있으므로 운영 중인 디스크에 직접 실행해서는 안 된다.

- `mklabel gpt`
- `mklabel msdos`
- `fdisk`의 `g`
- `fdisk`의 `o`

운영 환경에서는 **백업 → 변경 계획 수립 → 파티션 테이블 변경 → 파티션 확인 → 파일시스템 확인 → 마운트 상태 확인** 순으로 작업하는 것이 안전하다.
