## 1. 파일 시스템 개요

### 파일 시스템의 개념

**파일 시스템(File System)**은 저장 장치에 파일과 디렉토리를 저장하고 관리하기 위한 구조와 규칙이다.

일반적인 저장 구조는 다음과 같은 단계로 구성된다.

**디스크 → 파티션 → 파일 시스템 → 마운트 → 파일 및 디렉토리 사용**

| 구성 요소 | 설명 |
|---|---|
| 디스크 | 물리적 또는 가상 저장 장치 |
| 파티션 | 디스크의 논리적인 저장 영역 |
| 파일 시스템 | 파티션에 파일과 디렉토리를 저장하기 위한 구조 |
| 마운트 | 파일 시스템을 특정 디렉토리에 연결하는 작업 |
| 마운트 포인트 | 파일 시스템이 연결되는 디렉토리 |

파일 시스템을 생성한 것만으로는 일반적인 경로를 통해 파일을 사용할 수 없으며, **마운트 포인트에 파일 시스템을 마운트**해야 한다.

### CentOS의 주요 파일 시스템

CentOS 10.x 환경에서는 일반적인 서버 환경에서 **XFS와 EXT4**가 주요 파일 시스템으로 사용된다.

| 파일 시스템 | 특징 |
|---|---|
| EXT2 | 저널링을 지원하지 않는 전통적인 EXT 계열 파일 시스템 |
| EXT3 | EXT2에 **저널링** 기능을 추가한 파일 시스템 |
| EXT4 | EXT3의 기능을 확장한 현대적인 범용 파일 시스템 |
| XFS | 대용량 파일 및 병렬 I/O에 강점을 가진 **저널링 파일 시스템** |

### 파일 시스템 확인 방법

| 명령어 | 설명 |
|---|---|
| `cat /proc/filesystems` | 커널에서 지원하는 파일 시스템 목록 확인 |
| `man 5 filesystems` | 파일 시스템 종류에 대한 매뉴얼 확인 |
| `man 5 fs` | 파일 시스템 관련 매뉴얼 확인 |
| `man -k ext4` | `ext4`와 관련된 매뉴얼 검색 |
| `man -k xfs` | `xfs`와 관련된 매뉴얼 검색 |
| `lsblk -f` | 블록 장치와 파일 시스템 정보를 확인 |
| `blkid` | 블록 장치의 UUID 및 파일 시스템 정보를 확인 |

## 2. 파일 시스템 종류와 특징

### EXT2

**EXT2(Second Extended File System)**는 초기 Linux 환경에서 널리 사용된 파일 시스템이다.

- **저널링 기능이 없다.**
- 비정상적인 종료가 발생하면 파일 시스템 검사에 상대적으로 많은 시간이 필요할 수 있다.
- 현재 CentOS 10.x의 일반적인 서버 환경에서는 주력 파일 시스템으로 사용하지 않는다.

### EXT3

**EXT3**는 EXT2에 **저널링 기능**을 추가한 파일 시스템이다.

- 시스템 장애 발생 시 파일 시스템 복구 시간을 줄이는 데 유리하다.
- EXT2와의 호환성이 높다.
- 기존 EXT2에 저널을 추가하여 EXT3로 사용하는 방식도 가능하다.
- 현재 CentOS 10.x의 일반적인 신규 시스템에서는 EXT4 또는 XFS가 주로 사용된다.

### EXT4

**EXT4**는 EXT3를 확장한 파일 시스템으로, 범용 서버 및 데스크톱 환경에서 널리 사용된다.

주요 특징은 다음과 같다.

- **저널링 지원**
- **Extents** 기반의 블록 관리
- 대용량 파일 및 파일 시스템 지원
- 디렉토리 검색 성능 개선을 위한 **hashed B-tree**
- 온라인 조각 모음 지원
- 빠른 파일 시스템 검사 기능 지원
- 온라인 파일 시스템 확장 지원
- 파일 시스템 축소도 지원하지만, 일반적으로 **언마운트 및 별도의 파일 시스템 관리 절차가 필요**하다.

### XFS

**XFS(eXtended File System)**는 대용량 저장 환경과 높은 I/O 처리량을 고려하여 설계된 저널링 파일 시스템이다.

주요 특징은 다음과 같다.

- **메타데이터 저널링**
- 대용량 파일 및 파일 시스템에 적합
- 대규모 디렉토리 및 다수의 파일을 처리하는 환경에 강점
- 병렬 I/O 처리에 적합
- 온라인 파일 시스템 확장 지원
- **파일 시스템 축소는 지원하지 않음**
- 손상된 XFS 파일 시스템은 일반적인 `fsck`가 아니라 **`xfs_repair`**를 사용하여 복구한다.

### EXT4와 XFS 비교

| 항목 | EXT4 | XFS |
|---|---|---|
| 저널링 | 지원 | 지원 |
| 저널링 대상 | 파일 시스템 메타데이터 및 데이터 저널링 모드 지원 | 기본적으로 메타데이터 중심 |
| 대용량 파일 | 우수 | **매우 적합** |
| 대용량 디렉토리 | 우수 | **매우 적합** |
| 병렬 I/O | 우수 | **강점** |
| 파일 시스템 확장 | 온라인 확장 가능 | **온라인 확장 가능** |
| 파일 시스템 축소 | 지원 | **지원하지 않음** |
| 점검/복구 | `fsck`, `e2fsck` | `xfs_repair` |
| 범용 서버 | **적합** | 적합 |
| 대용량 DB/로그/스토리지 | 적합 | **권장** |

일반적인 선택 기준은 다음과 같이 정리할 수 있다.

| 환경 | 권장 파일 시스템 |
|---|---|
| 일반적인 Linux 서버 | **EXT4 또는 XFS** |
| 범용 애플리케이션 | **EXT4** |
| 대용량 데이터베이스 | **XFS** |
| 로그 서버 | **XFS** |
| 대용량 미디어 저장소 | **XFS** |
| 대규모 파일 및 디렉토리 | **XFS** |

## 3. 파일 시스템 생성

### 파티션 확인

파일 시스템을 생성하기 전에 **대상 파티션을 정확하게 확인**해야 한다.

| 명령어 | 설명 |
|---|---|
| `fdisk -l` | 전체 디스크와 파티션 정보 확인 |
| `fdisk -l /dev/nvme0n1` | 특정 디스크의 파티션 정보 확인 |
| `lsblk` | 블록 장치 구조 확인 |
| `lsblk -f` | 블록 장치와 파일 시스템 정보 확인 |

**파일 시스템 생성 명령은 지정된 파티션의 기존 데이터를 삭제할 수 있으므로 대상 장치를 반드시 확인해야 한다.**

### mkfs 명령어

**`mkfs`**는 파티션이나 블록 장치에 파일 시스템을 생성하는 명령어이다.

| 형식 | 설명 |
|---|---|
| `mkfs -t TYPE DEVICE` | 지정한 타입의 파일 시스템 생성 |
| `mkfs.TYPE DEVICE` | 특정 파일 시스템 생성 명령어 직접 사용 |

| 옵션 | 설명 |
|---|---|
| `-t TYPE` | 생성할 파일 시스템 종류 지정 |
| `-v` | 작업 상태 및 결과를 자세하게 출력 |

### EXT 계열 파일 시스템 생성

EXT 계열에서는 다음 명령어를 사용할 수 있다.

| 명령어 | 설명 |
|---|---|
| `mkfs.ext2 DEVICE` | EXT2 생성 |
| `mkfs.ext3 DEVICE` | EXT3 생성 |
| `mkfs.ext4 DEVICE` | EXT4 생성 |
| `mkfs -t ext4 DEVICE` | EXT4 생성 |

현재 CentOS 10.x의 일반적인 환경에서는 **EXT4 사용을 우선적으로 고려**할 수 있다.

### XFS 파일 시스템 생성

| 명령어 | 설명 |
|---|---|
| `mkfs.xfs DEVICE` | XFS 파일 시스템 생성 |
| `mkfs -t xfs DEVICE` | XFS 파일 시스템 생성 |

XFS는 파일 시스템 생성 시 기존 파일 시스템이 존재하는 장치를 대상으로 실행하면 기존 데이터가 손실될 수 있으므로 **대상 장치 확인이 필수**이다.

### 생성된 파일 시스템 확인

| 명령어 | 설명 |
|---|---|
| `lsblk -f` | 장치, 파일 시스템 타입, UUID 등을 확인 |
| `blkid` | 장치의 UUID, TYPE 등 확인 |
| `file -s DEVICE` | 블록 장치의 파일 시스템 정보를 확인하는 데 활용 |
| `df -hT` | 마운트된 파일 시스템의 타입과 사용량 확인 |

### 자주 사용하는 사용 예제

파일 시스템을 생성한 후 실제 타입과 UUID를 확인할 때는 다음과 같이 사용한다.

`lsblk -f`

`blkid`

## 4. 파일 시스템 점검 및 복구

### fsck

**`fsck(File System Check)`**는 파일 시스템의 무결성을 검사하고 필요한 경우 복구하는 명령어이다.

일반적인 EXT 계열 파일 시스템에서 사용한다.

| 명령어 | 설명 |
|---|---|
| `fsck DEVICE` | 파일 시스템을 검사하고 필요한 경우 대화형으로 수정 |
| `fsck -y DEVICE` | 모든 수정 질문에 `yes`로 응답 |
| `fsck -f DEVICE` | 파일 시스템 상태와 관계없이 강제 검사 |
| `fsck -n DEVICE` | 수정하지 않고 검사 |
| `e2fsck DEVICE` | EXT2/EXT3/EXT4 계열 파일 시스템을 직접 검사 |
| `fsck.ext4 DEVICE` | EXT4 파일 시스템 검사 |

### fsck 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-y` | 모든 수정 요청에 자동으로 `yes` 응답 |
| `-n` | 수정하지 않고 검사하는 **읽기 전용 방식** |
| `-f` | 정상 상태로 판단되더라도 강제로 검사 |
| `-b SUPERBLOCK` | 지정한 백업 Superblock을 사용하여 EXT 계열 파일 시스템 검사/복구 |

### xfs_repair

**XFS 파일 시스템은 `fsck` 대신 `xfs_repair`를 사용**하여 점검 및 복구한다.

| 명령어 | 설명 |
|---|---|
| `xfs_repair DEVICE` | XFS 파일 시스템 검사 및 복구 |
| `xfs_repair -n DEVICE` | 실제 변경 없이 검사 |
| `xfs_repair -L DEVICE` | 로그를 초기화하여 복구를 시도<br>데이터 손실 가능성이 있으므로 신중하게 사용 |

`xfs_repair -n`은 **실제 수정 없이 문제를 확인하는 사전 점검**에 유용하다.

### 파일 시스템 점검 시 주의사항

**마운트된 파일 시스템에 일반적인 파일 시스템 복구 도구를 실행하면 안 된다.**

특히 쓰기 가능한 상태로 사용 중인 파일 시스템을 검사하면 파일 시스템 구조와 실제 사용 상태가 동시에 변경되어 **추가적인 손상이나 데이터 불일치**가 발생할 수 있다.

| 대상 | 일반적인 처리 방법 |
|---|---|
| 별도의 데이터 파일 시스템 | `umount` 후 `fsck` 또는 `xfs_repair` |
| `/` | 정상 부팅 상태에서 직접 언마운트할 수 없으므로 **Rescue/Break 환경**에서 점검 |
| `/home` | 사용 중인 프로세스를 종료하고 언마운트 후 점검 |
| `/var` | 사용 중인 서비스에 주의하여 언마운트 후 점검 |
| `/boot` | 사용 상태를 확인한 후 언마운트 가능한 환경에서 점검 |

### 점검 결과 기록

파일 시스템 점검 결과를 로그 파일로 저장하면 문제 분석과 이력 관리에 유용하다.

| 명령어 | 설명 |
|---|---|
| `fsck -y DEVICE 2>&1 \| tee fsck.log` | 표준 출력과 오류 출력을 모두 로그 파일에 저장 |
| `cat fsck.log` | 저장된 점검 결과 확인 |

### EXT4 Superblock 복구

**Superblock**은 파일 시스템의 구조와 상태를 관리하는 핵심 메타데이터이다.

EXT4는 기본 Superblock 외에 **백업 Superblock**을 저장할 수 있다.

| 명령어 | 설명 |
|---|---|
| `dumpe2fs DEVICE` | EXT 계열 파일 시스템의 상세 정보 확인 |
| `dumpe2fs DEVICE \| grep -i superblock` | 백업 Superblock 위치 확인 |
| `dumpe2fs DEVICE \| grep -i 'block size'` | 블록 크기 확인 |
| `e2fsck -b SUPERBLOCK DEVICE` | 지정한 백업 Superblock을 사용하여 복구 |

백업 Superblock 위치는 **파일 시스템의 블록 크기 및 생성 옵션 등에 따라 달라질 수 있으므로 임의의 번호를 사용하면 안 된다.**

### 자주 사용하는 사용 예제

백업 Superblock 위치를 확인한 후 해당 번호를 사용하여 EXT4 파일 시스템을 복구한다.

`dumpe2fs DEVICE | grep -i superblock`

`e2fsck -b BACKUP_SUPERBLOCK DEVICE`

### root 파일 시스템 점검

`/` 파일 시스템이 XFS인 경우 정상적으로 부팅된 시스템에서는 `/`를 언마운트할 수 없기 때문에 일반적인 방법으로 `xfs_repair`를 실행할 수 없다.

이 경우 **Rescue 환경 또는 `rd.break`를 이용한 부팅 환경**에서 점검한다.

### GRUB `rd.break`를 이용한 점검

GRUB에서 커널 부팅 항목을 편집하여 **`rd.break`**를 추가하면 일반적인 시스템 부팅 이전의 긴급 셸 환경으로 진입할 수 있다.

일반적인 절차는 다음과 같다.

1. 시스템을 재부팅한다.
2. GRUB 메뉴에서 사용할 커널 항목을 선택한다.
3. `e` 키를 눌러 부팅 항목을 편집한다.
4. `linux`로 시작하는 커널 라인으로 이동한다.
5. 마지막에 `rd.break`를 추가한다.
6. `Ctrl + X`로 부팅한다.
7. `/sysroot`가 마운트되어 있다면 필요한 경우 언마운트한다.
8. 대상 XFS 장치에 `xfs_repair`를 실행한다.
9. 작업이 완료되면 시스템을 재부팅한다.

| 항목 | 설명 |
|---|---|
| `e` | GRUB 부팅 항목 편집 |
| `linux ...` | 커널 부팅 파라미터가 포함된 라인 |
| `rd.break` | 초기 부팅 과정에서 긴급 셸로 진입 |
| `Ctrl + X` | 편집한 부팅 설정으로 부팅 |

## 5. 파일 시스템 사용량 측정

### df

**`df(Disk Free)`**는 파일 시스템 단위의 디스크 사용량을 확인하는 명령어이다.

주로 **파티션 또는 마운트된 파일 시스템의 전체 용량, 사용량, 여유 공간**을 확인할 때 사용한다.

기본 출력에는 일반적으로 다음 정보가 포함된다.

| 항목 | 설명 |
|---|---|
| Filesystem | 파일 시스템 또는 장치 |
| Type | 파일 시스템 종류 |
| Size | 전체 크기 |
| Used | 사용 중인 공간 |
| Avail | 사용 가능한 공간 |
| Use% | 사용률 |
| Mounted on | 마운트 지점 |

### df 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-k` | KiB 단위에 가까운 1K 블록 단위로 표시 |
| `-m` | MiB 단위에 가까운 MB 단위로 표시 |
| `-h` | 사람이 읽기 쉬운 단위로 표시 |
| `-i` | 블록 사용량 대신 inode 사용량 표시 |
| `-a` | 의사 파일 시스템 등을 포함하여 가능한 모든 파일 시스템 표시 |
| `-t TYPE` | 지정한 파일 시스템 타입만 표시 |
| `-T` | 파일 시스템 타입을 함께 표시 |

### 자주 사용하는 사용 예제

전체 파일 시스템의 용량과 타입을 사람이 읽기 쉬운 형태로 확인한다.

`df -hT`

특정 경로가 속한 파일 시스템의 사용량을 확인한다.

`df -hT /home`

특정 파일 시스템 타입만 확인한다.

`df -hT -t xfs`

`df -hT -t ext4`

`-t`를 여러 번 사용할 경우 조건의 의미를 확인해야 하며, 단순히 여러 타입을 선택하려면 실제 출력 결과를 확인하는 것이 안전하다.

### du

**`du(Disk Usage)`**는 디렉토리 또는 파일이 실제로 사용하는 디스크 공간을 확인하는 명령어이다.

`df`가 **파일 시스템 단위**라면 `du`는 **디렉토리 및 파일 단위**의 사용량 분석에 적합하다.

### du 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-s` | 지정한 경로의 총합만 표시 |
| `-a` | 파일까지 포함하여 사용량 표시 |
| `-k` | KiB에 해당하는 1K 블록 단위로 표시 |
| `-m` | MiB에 해당하는 MB 단위로 표시 |
| `-h` | 사람이 읽기 쉬운 단위로 표시 |
| `-H` | SI 단위인 KB, MB, GB 등을 사용하여 표시 |

### 자주 사용하는 사용 예제

특정 디렉토리의 전체 사용량만 확인한다.

`du -sh /var`

특정 디렉토리 바로 아래의 항목별 사용량을 확인한다.

`du -sh /var/*`

파일을 포함하여 하위 항목의 사용량을 확인한다.

`du -ah /var`

현재 디렉토리의 하위 항목을 사용량이 큰 순서로 정렬한다.

`du -sh * | sort -hr`

### df와 du의 차이

| 명령어 | 기준 | 주요 용도 |
|---|---|---|
| `df` | **파일 시스템** | 파티션 전체 용량, 사용량, 여유 공간 확인 |
| `du` | **파일/디렉토리** | 특정 디렉토리 또는 파일이 차지하는 공간 분석 |

**디스크가 부족한 상황에서는 `df`로 어느 파일 시스템이 부족한지 확인한 후 `du`로 어떤 디렉토리가 많은 공간을 사용하는지 분석하는 방식이 일반적이다.**

## 6. 파일 시스템 사용량 분석 명령어

### 파일 시스템별 사용량 확인

| 명령어 | 설명 |
|---|---|
| `df -hT` | 전체 파일 시스템의 용량 및 타입 확인 |
| `df -hT -t xfs` | XFS 파일 시스템만 확인 |
| `df -hT -t ext4` | EXT4 파일 시스템만 확인 |
| `df -hT -x tmpfs -x devtmpfs` | 지정한 파일 시스템 타입을 제외하고 확인 |

### 디렉토리별 사용량 확인

| 명령어 | 설명 |
|---|---|
| `du -sh /var` | `/var` 전체 사용량 확인 |
| `du -sh /var/*` | `/var` 바로 아래 항목별 사용량 확인 |
| `du -sh /var/* \| sort -hr` | 사용량이 큰 순서로 정렬 |
| `du -ah /var` | 파일까지 포함하여 전체 사용량 확인 |

### 대용량 파일 검색

`find`의 **`-size` 옵션**을 이용하면 특정 크기 이상의 파일을 검색할 수 있다.

| 명령어 | 설명 |
|---|---|
| `find /var -type f -size +300M` | `/var` 아래에서 300MiB 초과 파일 검색 |
| `find /var -type f -size +1G` | `/var` 아래에서 1GiB 초과 파일 검색 |

`find`의 크기 단위는 옵션의 표현 방식에 따라 해석되므로 **정확한 단위가 필요한 경우 `man find`로 확인**하는 것이 좋다.

### 파일을 사용 중인 프로세스 확인

**`lsof`**는 열린 파일과 이를 사용 중인 프로세스 정보를 확인하는 명령어이다.

| 명령어 | 설명 |
|---|---|
| `lsof FILE` | 특정 파일을 열고 있는 프로세스 확인 |
| `lsof +D DIRECTORY` | 특정 디렉토리 아래의 열린 파일 확인 |
| `lsof /path/to/file` | 지정한 파일을 사용 중인 프로세스 확인 |

### 자주 사용하는 사용 예제

파일 시스템 사용량이 높은 경우 다음 순서로 원인을 찾을 수 있다.

`df -hT`

`du -sh /var/* | sort -hr`

`find /var -type f -size +300M`

`lsof /path/to/file`

## 7. 파일 시스템 모니터링

### 모니터링의 기본 구성

파일 시스템 모니터링은 일반적으로 다음과 같은 방식으로 구성할 수 있다.

**사용량 확인 → 임계치 비교 → 경고 메시지 생성 → 관리자 알림**

`df`의 사용률을 주기적으로 확인하고 특정 임계치를 초과하면 관리자에게 알림을 전송하는 방식으로 구현할 수 있다.

### 사용량 임계치 모니터링

예를 들어 특정 파일 시스템의 사용률이 **80%를 초과하는 경우** 경고를 발생시키도록 구성할 수 있다.

스크립트에서 사용할 수 있는 주요 명령어는 다음과 같다.

| 명령어 | 용도 |
|---|---|
| `df` | 파일 시스템 사용량 확인 |
| `tail` | 마지막 출력 행 추출 |
| `awk` | 특정 필드 추출 및 데이터 처리 |
| `date` | 현재 날짜 및 시간 확인 |
| `sleep` | 일정 시간 동안 대기 |
| `mailx` | 메일 전송 |
| `tee` | 화면 출력과 파일 저장을 동시에 수행 |

파일 시스템 모니터링 스크립트는 다음과 같은 변수 구조로 구성할 수 있다.

| 변수 | 용도 |
|---|---|
| `FS` | 모니터링할 파일 시스템 |
| `FS_USAGE` | 현재 파일 시스템 사용률 |
| `MAILON` | 동일 날짜의 중복 알림을 방지하기 위한 값 |
| `MAILCONTENT` | 메일 본문으로 사용할 임시 파일 |

### 백그라운드 실행

지속적으로 파일 시스템을 감시하는 스크립트는 백그라운드에서 실행할 수 있다.

| 명령어 | 설명 |
|---|---|
| `chmod 755 SCRIPT` | 스크립트에 실행 권한 부여 |
| `./SCRIPT` | 포그라운드에서 실행 |
| `./SCRIPT &` | 백그라운드 실행 |
| `nohup ./SCRIPT &` | 터미널 종료 후에도 계속 실행하도록 실행 |

모니터링 스크립트는 단순한 실습 목적을 넘어 실제 운영 환경에서는 **systemd 서비스 및 timer, 모니터링 시스템, 로그 관리 시스템** 등을 사용하는 것이 더 적절할 수 있다.

### 자주 사용하는 사용 예제

파일 시스템 사용률을 지속적으로 확인하는 스크립트를 백그라운드에서 실행한다.

`nohup /root/bin/fs_mon.sh &`

### 핵심 명령어 조합

`fsck -n DEVICE`

### 최종 핵심 정리

- **EXT4 → `fsck` / `e2fsck`**
- **XFS → `xfs_repair`**
- **마운트된 파일 시스템은 일반적인 복구 작업 전에 반드시 언마운트 여부를 확인**
- **`/` 파일 시스템은 정상 부팅 상태에서 직접 언마운트할 수 없으므로 Rescue 환경 등을 활용**
- **`df` → 파일 시스템 단위의 사용량 확인**
- **`du` → 파일 및 디렉토리 단위의 사용량 확인**
- **`find` → 대용량 파일 탐색**
- **`lsof` → 특정 파일을 사용 중인 프로세스 확인**
- **`lsblk -f`, `blkid` → 장치와 파일 시스템 및 UUID 확인**
- **`dumpe2fs` → EXT 계열 파일 시스템 구조와 Superblock 정보 확인**
- **XFS는 파일 시스템 축소를 지원하지 않으므로 파일 시스템 설계 단계에서 용량 계획이 중요**
