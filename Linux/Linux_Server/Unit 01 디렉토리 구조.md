## 1. 리눅스 파일 시스템 계층 구조

### FHS와 파일 시스템 계층

리눅스의 파일 시스템은 **역전된 트리(Tree) 구조**를 가지며, 최상위에는 **루트 디렉토리 `/`**가 존재한다.

- 모든 파일과 디렉토리는 `/`를 기준으로 계층적으로 구성된다.
- 디렉토리의 목적과 파일의 성격에 따라 파일이 구분되어 저장된다.
- 리눅스의 파일 시스템 구조는 **FHS(Filesystem Hierarchy Standard)**를 기반으로 구성된다.
- 동일한 목적의 파일을 일정한 위치에 배치하므로 프로그램 개발, 시스템 관리 및 파일 탐색이 용이하다.
- 시스템에 따라 일부 디렉토리의 구성이나 세부 내용은 달라질 수 있다.

### 기본 디렉토리 구조

주요 최상위 디렉토리는 다음과 같다.

| 디렉토리 | 주요 용도 |
|---|---|
| `/` | **최상위 루트 디렉토리** |
| `/boot` | 부팅에 필요한 커널 및 부트 관련 파일 |
| `/dev` | 장치 파일 |
| `/etc` | 시스템 및 서비스 설정 파일 |
| `/home` | 일반 사용자의 홈 디렉토리 |
| `/media` | 이동식 장치의 마운트 지점 |
| `/mnt` | 임시 파일 시스템 마운트 지점 |
| `/opt` | 추가 응용 프로그램 설치 영역 |
| `/proc` | 프로세스 및 커널 정보를 제공하는 가상 파일 시스템 |
| `/root` | root 사용자의 홈 디렉토리 |
| `/run` | 현재 부팅 이후 생성된 런타임 데이터 |
| `/srv` | 서비스에서 제공하는 데이터 |
| `/sys` | 커널 및 장치 정보를 제공하는 가상 파일 시스템 |
| `/tmp` | 임시 파일 저장 공간 |
| `/usr` | 사용자 프로그램, 라이브러리 및 공유 데이터 |
| `/var` | 로그, 캐시 등 지속적으로 변경되는 가변 데이터 |

### CentOS의 주요 심볼릭 링크

CentOS 7 이후 계열에서는 다음과 같은 주요 디렉토리가 `/usr` 아래의 디렉토리를 가리키는 **심볼릭 링크**로 구성된다.

| 경로 | 연결 대상 | 의미 |
|---|---|---|
| `/bin` | `/usr/bin` | 일반 사용자 명령어 |
| `/sbin` | `/usr/sbin` | 시스템 관리 명령어 |
| `/lib` | `/usr/lib` | 라이브러리 |
| `/lib64` | `/usr/lib64` | 64비트 라이브러리 |

## 2. 주요 디렉토리 구조

### 루트 디렉토리 `/`

**`/`는 리눅스 파일 시스템의 최상위 디렉토리**이다.

- 모든 디렉토리의 시작점이다.
- 다른 파일 시스템이 마운트되는 기준점이 된다.
- `/root`와 혼동하지 않아야 한다.
  - `/` : 전체 파일 시스템의 최상위 디렉토리
  - `/root` : root 사용자의 홈 디렉토리

| 명령어 | 설명 |
|---|---|
| `ls /` | 루트 디렉토리의 내용을 확인 |
| `tree -d -L 1 /` | 루트 바로 아래의 디렉토리 구조를 확인 |
| `cd /` | 루트 디렉토리로 이동 |

### `/root`

**root 사용자의 홈 디렉토리**이다.

- 일반 사용자의 홈 디렉토리인 `/home/UserName`과 구분된다.
- root 사용자의 개인 환경 설정 파일 등이 저장된다.
- 대표적인 환경 파일로 `.bash_profile`, `.bashrc` 등이 있다.

| 경로 | 용도 |
|---|---|
| `/root/.bash_profile` | root 사용자의 로그인 환경 설정 |
| `/root/.bashrc` | root 사용자의 Bash 환경 설정 |
| `/root/.bash_history` | Bash 명령어 이력 |
| `/root/.vimrc` | Vim 사용자 설정 |

### `/usr`

**사용자 프로그램, 라이브러리 및 공유 가능한 데이터를 저장하는 주요 디렉토리**이다.

| 하위 디렉토리 | 주요 용도 |
|---|---|
| `/usr/bin` | 일반 사용자 명령어 및 실행 파일 |
| `/usr/sbin` | 시스템 관리 명령어 |
| `/usr/lib` | 라이브러리 |
| `/usr/local` | 시스템 관리자가 직접 설치하는 로컬 소프트웨어 |

### `/etc`

**시스템 전반의 설정 파일이 저장되는 디렉토리**이다.

주요 설정 대상은 다음과 같다.

- 시스템 초기화 및 부팅 설정
- 사용자 및 그룹 관련 설정
- 네트워크 설정
- 서비스 설정
- 보안 관련 설정
- 파일 시스템 관련 설정
- PAM 관련 설정

| 경로 | 용도 |
|---|---|
| `/etc/passwd` | 사용자 계정 정보 |
| `/etc/shadow` | 사용자 암호 관련 정보 |
| `/etc/group` | 그룹 정보 |
| `/etc/hosts` | 호스트 이름과 IP 주소의 로컬 매핑 |
| `/etc/pam.d/` | PAM 서비스 설정 |
| `/etc/security/` | 보안 관련 설정 |

### `/var`

**시스템에서 지속적으로 변경되는 가변 데이터**를 저장한다.

| 하위 디렉토리 | 주요 용도 |
|---|---|
| `/var/log` | 시스템 및 서비스 로그 |
| `/var/www/html` | 웹 서버의 기본 콘텐츠 영역으로 사용 가능 |
| `/var/tmp` | 재부팅 후에도 보존될 수 있는 임시 파일 영역 |

주요 데이터에는 다음이 포함될 수 있다.

- 시스템 로그
- 서비스 로그
- 캐시
- 스풀 데이터
- 데이터베이스 관련 데이터
- 웹 콘텐츠

### `/run`

**현재 부팅 이후 실행 중인 시스템의 런타임 데이터**를 저장한다.

- 프로세스 ID(PID) 파일
- 소켓
- 잠금 파일
- 기타 서비스의 런타임 상태 정보

`/run`의 내용은 시스템 재부팅 시 새로 생성된다.

과거의 `/var/run`, `/var/lock`은 현재 시스템에서 `/run`과 연결되어 사용되는 경우가 많다.

### `/home`

**일반 사용자의 홈 디렉토리**가 저장되는 영역이다.

| 경로 | 용도 |
|---|---|
| `/home/UserName` | 일반 사용자 UserName의 홈 디렉토리 |
| `/home/UserName/.bashrc` | 사용자 Bash 환경 설정 |
| `/home/UserName/.bash_profile` | 사용자 로그인 환경 설정 |

일반 사용자의 개인 데이터 및 사용자별 설정 파일을 저장한다.

### `/tmp`

**프로그램 및 사용자가 임시로 사용하는 파일을 저장하는 디렉토리**이다.

- 임시 작업 파일을 저장한다.
- 시스템의 `systemd-tmpfiles` 정책에 따라 오래된 임시 파일이 정리될 수 있다.
- 삭제 주기는 시스템 정책에 따라 달라질 수 있으므로 특정 일수를 일반 규칙으로 기억하지 않는다.

### `/boot`

**시스템 부팅에 필요한 파일**이 저장되는 디렉토리이다.

| 파일 또는 디렉토리 | 주요 용도 |
|---|---|
| `vmlinuz-*` | Linux 커널 |
| `initramfs-*` | 초기 RAM 파일 시스템 |
| `grub2/` | GRUB 관련 파일 |
| `efi/` | UEFI 부팅 관련 파일 |

### `/bin`과 `/sbin`

CentOS 7 이후 계열에서는 `/bin`과 `/sbin`이 각각 `/usr/bin`, `/usr/sbin`으로 연결되는 구조를 사용한다.

| 디렉토리 | 주요 용도 | 예 |
|---|---|---|
| `/bin` → `/usr/bin` | 일반 사용자가 사용하는 기본 명령어 | `ls`, `cp`, `mv`, `rm` |
| `/sbin` → `/usr/sbin` | 시스템 관리에 사용되는 명령어 | `fsck`, `fdisk` |

### `/mnt`와 `/media`

파일 시스템을 **마운트**하기 위한 디렉토리이다.

| 경로 | 주요 용도 |
|---|---|
| `/mnt` | 임시 마운트 지점 |
| `/media` | 이동식 미디어의 마운트 지점 |
| `/run/media/UserName/` | 현재 데스크톱 환경에서 사용자별 이동식 미디어 마운트에 사용 |

자료의 CentOS 버전별 예시는 과거 버전의 관행을 설명한 것이므로, 현재 시스템에서는 실제 마운트 정책을 확인하여 사용한다.

### `/lib`과 `/lib64`

프로그램 실행에 필요한 **라이브러리 파일**을 저장한다.

| 경로 | 의미 |
|---|---|
| `/lib` → `/usr/lib` | 일반 라이브러리 |
| `/lib64` → `/usr/lib64` | 64비트 라이브러리 |

현재 CentOS 계열에서는 `/usr` 통합 구조에 따라 `/lib`, `/lib64`가 심볼릭 링크로 구성될 수 있다.

### `/dev`

**장치(Device)를 파일 형태로 표현하는 디렉토리**이다.

대표적인 장치는 다음과 같다.

- 하드 디스크
- SSD
- CD/DVD 장치
- 터미널
- 루프백 장치
- 기타 하드웨어 장치

리눅스에서는 장치를 **장치 파일(Device File)**로 다룬다.

| 장치 파일 종류 | 설명 |
|---|---|
| Block Device | 블록 단위로 데이터를 처리하는 장치 |
| Character Device | 문자 단위로 데이터를 처리하는 장치 |

### `/proc`

**프로세스 및 커널 관련 정보를 제공하는 가상 파일 시스템**이다.

- 실제 디스크에 일반 파일 형태로 저장되는 영역이 아니다.
- 커널이 현재 시스템 상태에 따라 동적으로 정보를 제공한다.
- 프로세스 정보, CPU, 메모리 등의 시스템 정보를 확인할 수 있다.

### `/opt`, `/srv`, `/sys`

| 디렉토리 | 주요 용도 |
|---|---|
| `/opt` | 추가 설치된 응용 프로그램 및 패키지 |
| `/srv` | 시스템이 제공하는 서비스의 데이터 |
| `/sys` | 커널의 장치 및 시스템 정보를 제공하는 가상 파일 시스템 |

## 3. 파일 시스템 구조 확인 명령어

### 디렉토리 구조 확인

| 명령어 | 설명 |
|---|---|
| `tree -d -L 1 /` | `/` 바로 아래의 디렉토리 구조를 확인 |
| `ls /` | `/`의 디렉토리 및 파일 목록 확인 |
| `ls -a /root` | `/root`의 숨김 파일을 포함하여 확인 |
| `ls -l /boot` | `/boot`의 상세 목록 확인 |

### 파일 시스템 계층 매뉴얼 확인

리눅스의 파일 시스템 계층에 대한 공식적인 설명은 매뉴얼 페이지를 통해 확인할 수 있다.

| 명령어 | 설명 |
|---|---|
| `man 7 hier` | 전통적인 파일 시스템 계층 구조 설명 |
| `man 7 file-hierarchy` | systemd 기반의 현대적인 파일 시스템 계층 구조 설명 |

**`man 7 hier`**와 **`man 7 file-hierarchy`**는 디렉토리의 목적을 확인할 때 유용하다.

### 디렉토리 검색

| 명령어 | 설명 |
|---|---|
| `find / -name bin -type d` | 이름이 `bin`인 디렉토리를 검색 |
| `find / -name sbin -type d` | 이름이 `sbin`인 디렉토리를 검색 |
| `find / \( -name bin -o -name sbin \) -type d` | `bin` 또는 `sbin`이라는 이름의 디렉토리를 검색 |

### 장치 파일 검색

| 명령어 | 설명 |
|---|---|
| `find /dev -type b -ls` | `/dev`에서 블록 장치 파일을 검색 |
| `find /dev -type c -ls` | `/dev`에서 문자 장치 파일을 검색 |

## 4. 주요 시스템 설정 파일

### `/etc/hosts`

`/etc/hosts`는 **호스트 이름과 IP 주소를 로컬에서 연결**하는 파일이다.

| 항목 | 설명 |
|---|---|
| IP 주소 | 대상 호스트의 IP 주소 |
| FQDN | 정규화된 호스트 이름 |
| HostName | 시스템에서 사용할 호스트 이름 |

예를 들어 여러 테스트 서버를 구성한 경우 서버 이름을 IP 주소와 연결하여 사용할 수 있다.

| 명령어 | 설명 |
|---|---|
| `vi /etc/hosts` | `/etc/hosts` 편집 |
| `ping -c 2 UserName` | 지정한 호스트 이름으로 2회 ping 테스트 |

### 자주 사용하는 사용 예제

`/etc/hosts`에 서버 정보를 등록한 뒤 호스트 이름으로 통신이 가능한지 확인한다.

`ping -c 2 UserName`

## 5. 공개키 인증

### SSH 공개키 인증의 개념

**Public Key Authentication**은 SSH 접속 시 공개키와 개인키를 이용하여 인증하는 방식이다.

- **Private Key(개인키)** : 사용자 시스템에 안전하게 보관
- **Public Key(공개키)** : 원격 서버에 등록
- 서버에 공개키가 등록되어 있으면 개인키를 이용하여 비밀번호 입력 없이 SSH 인증을 수행할 수 있다.
- 개인키는 다른 사용자에게 공유하지 않는다.

### SSH 키 생성

| 명령어 | 설명 |
|---|---|
| `cd ~/.ssh` | SSH 관련 파일을 저장하는 디렉토리로 이동 |
| `ssh-keygen` | SSH 키 쌍을 생성 |
| `ssh-keygen -t TYPE` | 지정한 키 타입으로 키 생성 |

`ssh-keygen`을 실행하면 일반적으로 다음 항목을 입력한다.

| 항목 | 설명 |
|---|---|
| 저장 경로 | 생성할 키 파일의 위치 |
| Passphrase | 개인키 보호를 위한 암호 |
| 확인 입력 | Passphrase 재입력 |

### 공개키 배포

| 명령어 | 설명 |
|---|---|
| `ssh-copy-id -i ~/.ssh/id_rsa.pub UserName` | 지정한 공개키를 원격 계정에 등록 |
| `ssh UserName hostname` | SSH로 원격 호스트의 hostname 명령 실행 |

자료에서는 `id_rsa.pub`를 예시로 사용하지만, 실제 키 파일명은 `ssh-keygen`에서 선택한 키 종류와 생성 방식에 따라 달라질 수 있다.

### SSH 연결 확인

여러 서버에 공개키를 배포한 후 반복문을 이용하여 연결 상태를 확인할 수 있다.

### 자주 사용하는 사용 예제

`for i in UserName1 UserName2 UserName3; do ssh $i hostname; done`

위 명령은 여러 호스트에 차례로 SSH 접속하여 각 호스트의 `hostname`을 실행한다.

## 6. 환경 파일 관리

### 주요 환경 파일

Linux의 Bash 환경은 시스템 전체 설정과 사용자별 설정 파일을 통해 구성할 수 있다.

| 파일 | 적용 범위 및 용도 |
|---|---|
| `/etc/profile` | 시스템 전체의 로그인 셸 환경 설정 |
| `/etc/bashrc` | 시스템 전체 Bash 설정 |
| `/etc/profile.d/` | 시스템 전체에 적용할 추가 셸 설정 |
| `~/.bash_profile` | 사용자 로그인 환경 설정 |
| `~/.bashrc` | 사용자 Bash 환경 설정 |
| `~/.bash_logout` | 로그인 셸 종료 시 처리할 설정 |

### 환경 파일 정리

기존에 추가한 환경 설정을 제거할 경우 관련 파일의 내용을 확인하고 불필요한 설정을 삭제한다.

| 명령어 | 설명 |
|---|---|
| `vi /etc/profile` | 시스템 로그인 환경 설정 편집 |
| `vi /etc/bashrc` | 시스템 Bash 설정 편집 |
| `vi ~/.bash_profile` | 사용자 로그인 환경 설정 편집 |
| `vi ~/.bashrc` | 사용자 Bash 설정 편집 |
| `vi ~/.bash_logout` | 사용자 로그아웃 환경 설정 편집 |
| `rm -f /etc/profile.d/test.sh` | 특정 환경 설정 스크립트 삭제 |

### 환경 정리 스크립트

여러 환경 파일에 동일한 설정이 추가된 경우 `sed` 등을 이용하여 일괄적으로 제거할 수 있다.

| 명령어 | 설명 |
|---|---|
| `chmod 700 /root/bin/env_unconf.sh` | 소유자에게만 읽기·쓰기·실행 권한 부여 |
| `rm -f /etc/profile.d/test.sh` | 지정된 환경 설정 파일 삭제 |
| `sed -i 'PATTERN' FILE` | 파일의 내용을 직접 수정 |

환경 파일을 일괄 변경하는 스크립트는 **삭제 대상과 패턴을 충분히 확인한 후 실행**해야 한다.

## 7. 가상 머신 스냅샷

### 스냅샷의 개념

**스냅샷(Snapshot)**은 가상 머신의 특정 시점 상태를 저장하여 이후 해당 상태로 되돌릴 수 있도록 하는 기능이다.

- 운영체제 설정 변경 전 상태를 보존할 수 있다.
- 실습 환경을 초기 상태로 되돌릴 때 유용하다.
- 가상 머신이 실행 중이거나 종료된 상태에서도 사용할 수 있는지는 사용하는 가상화 제품 및 설정에 따라 달라질 수 있다.

### 스냅샷 생성

VMware 환경에서는 다음과 같은 메뉴를 통해 스냅샷을 생성할 수 있다.

**VM → Snapshot → Take Snapshot**

스냅샷 생성 시 다음 정보를 입력할 수 있다.

| 항목 | 설명 |
|---|---|
| Name | 스냅샷 식별을 위한 이름 |
| Description | 스냅샷 생성 목적 및 상태에 대한 설명 |

### 자주 사용하는 사용 예제

실습 시작 전 `main`, `server1`, `server2` 등의 가상 머신 상태를 스냅샷으로 저장하여 설정 변경이나 실습 오류 발생 시 이전 상태로 복구할 수 있다.
