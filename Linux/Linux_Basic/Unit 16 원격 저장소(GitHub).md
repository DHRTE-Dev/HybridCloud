## 1. Git 환경 설정 및 저장소 초기화

### 패키지 설치 및 사용자 정보 설정

Git을 사용하기 위해서는 시스템에 **Git 패키지**를 설치한 후 작성자 정보를 설정해야 합니다. 설정된 **사용자 이름**과 **이메일 주소**는 커밋 이력의 작성자 정보로 기록됩니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `yum -y install git` | 패키지 관리자를 통한 **Git 설치**를 진행합니다.<br>`git-core` 패키지로 설치할 수도 있습니다. |
| `git config --global user.name <이름>` | 전역 **사용자 이름**을 설정합니다. |
| `git config --global user.email <이메일>` | 전역 **사용자 이메일**을 설정합니다.<br>원격 저장소 계정과 동일하게 설정합니다. |
| `git config --list` | 현재 적용된 전체 **Git 설정 목록**을 출력합니다. |
| `cat ~/.gitconfig` | 사용자 홈 디렉터리에 저장된 **전역 설정 파일**의 내용을 확인합니다. |

### 자주 사용되는 예제
- `git config --global user.name "Your_Name"`
- `git config --global user.email "Your_Email@gmail.com"`
- `git config --list`
- `cat ~/.gitconfig`

### 저장소 초기화 및 상태 확인

디렉터리를 Git으로 관리하기 위해서는 **로컬 저장소 초기화** 작업이 필요합니다. 초기화가 완료되면 내부 관리용 **.git 숨김 디렉터리**가 생성됩니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git init` | 현재 작업 디렉터리를 **Git 로컬 저장소**로 초기화합니다. |
| `git status` | **작업 디렉터리**와 **스테이징 영역**의 파일 상태를 확인합니다. |
| `git status -s` | 파일 상태를 **요약된 형태**로 간결하게 출력합니다. |
| `tree .git` | 생성된 **.git 내부 구조**를 트리 형태로 확인합니다. |

### 자주 사용되는 예제
- `git init`
- `git status`
- `tree .git`

## 2. 파일 추적 및 커밋 관리

### 스테이징 영역 추가 및 관리

파일의 변경 사항을 커밋하기 전 **스테이징 영역(Staging Area/Index)**에 올려 관리 대상으로 지정합니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git add <파일명>` | 지정한 특정 파일을 **스테이징 영역**에 추가합니다. |
| `git add .` | 현재 디렉터리의 모든 변경 사항을 **스테이징 영역**에 추가합니다. |
| `git add -A` | 작업 공간 내의 모든 변경 및 삭제된 파일을 **스테이징 영역**에 일괄 추가합니다. |
| `git rm --cached <파일명>` | 스테이징 영역에서 파일을 제거하고 **추적 대상에서 제외**합니다. |

### 자주 사용되는 예제
- `git add README.md`
- `git add .`
- `git add -A`

### 커밋 생성 및 이력 조회

스테이징 영역에 등록된 파일 변경 건을 하나의 단위로 묶어 **로컬 저장소**에 기록합니다. **커밋 메시지**를 작성하여 변경 목적을 명시해야 합니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git commit -m "<메시지>"` | 스테이징된 변경 사항을 지정한 **커밋 메시지**와 함께 기록합니다. |
| `git commit -am "<메시지>"` | 추적 중인 파일의 변경 사항을 **자동 스테이징 및 커밋**을 동시에 수행합니다. |
| `git log` | 저장소의 전체 **커밋 이력**을 상세하게 조회합니다. |
| `git log --oneline` | 커밋 이력을 **한 줄로 간결하게** 출력합니다. |
| `git log --graph` | **브랜치 및 병합 흐름**을 시각적 그래프로 표시합니다. |

### 자주 사용되는 예제
- `git commit -m "first commit"`
- `git log --oneline`

## 3. 브랜치 관리 및 작업 분기

### 브랜치 조회 및 생성

**브랜치(Branch)**는 독립적으로 작업을 진행할 수 있는 분기점입니다. 기본 생성되는 브랜치명을 변경하거나 목적에 맞는 새 브랜치를 생성하여 관리합니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git branch` | 현재 로컬에 존재하는 **브랜치 목록**을 조회합니다. |
| `git branch -v` | 각 브랜치의 **최신 커밋 정보**를 함께 조회합니다. |
| `git branch <브랜치명>` | 지정한 이름으로 **새로운 브랜치**를 생성합니다. |
| `git branch -M <새 브랜치명>` | 현재 브랜치의 이름을 **강제로 변경**합니다.<br>(예: `master` -> `main`) |
| `git branch -d <브랜치명>` | 작업이 완료된 **브랜치를 삭제**합니다. |

### 자주 사용되는 예제
- `git branch`
- `git branch -v`
- `git branch -M main`

### 브랜치 전환 및 병합

작업할 **브랜치를 전환**하거나 다른 브랜치에서 완료된 작업 내역을 **기본 브랜치로 병합**합니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git switch <브랜치명>` | 지정한 **브랜치로 전환**합니다. |
| `git switch -c <브랜치명>` | 새로운 브랜치를 **생성함과 동시에 전환**합니다. |
| `git checkout <브랜치명>` | 지정한 **브랜치로 전환**합니다.<br>(이전 버전 표준 명령어) |
| `git merge <브랜치명>` | 지정한 브랜치의 변경 사항을 현재 브랜치로 **병합**합니다. |

### 자주 사용되는 예제
- `git switch main`
- `git switch -c feature/login`
- `git merge feature/login`

## 4. 원격 저장소 연동 및 동기화

### 원격 저장소 연결 및 설정

GitHub 등 **원격 저장소(Remote Repository)**와 로컬 저장소를 연결하고 관리하는 설정 과정입니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git remote add <별칭> <URL>` | 로컬 저장소에 **원격 저장소 URL**을 연결합니다.<br>기본 별칭은 `origin`을 주로 사용합니다. |
| `git remote -v` | 연결된 **원격 저장소의 상세 목록**과 URL을 조회합니다. |
| `git remote remove <별칭>` | 지정한 **원격 저장소 연결을 해제**합니다. |
| `git remote set-url <별칭> <신규 URL>` | 기존 원격 저장소의 **접속 URL을 변경**합니다. |

### 자주 사용되는 예제
- `git remote add origin https://github.com/Your_ID/Repository_Name.git`
- `git remote -v`

### 코드 업로드 및 다운로드

로컬에서 작업한 커밋을 **원격 저장소로 업로드(Push)**하거나, 원격 저장소의 최신 변경 사항을 **로컬 저장소로 다운로드(Pull/Fetch)**합니다.

| 명령어 / 옵션 | 기능 및 설명 |
| --- | --- |
| `git push -u <원격지> <브랜치>` | 로컬 브랜치 커밋을 원격 저장소로 **업로드**합니다.<br>`-u` 옵션으로 상향 추적(Upstream)을 설정합니다. |
| `git push <원격지> <브랜치>` | 업스트림이 설정된 상태에서 커밋을 **원격 저장소로 업로드**합니다. |
| `git pull <원격지> <브랜치>` | 원격 저장소의 최신 변경 사항을 가져와 **현재 브랜치와 병합**합니다. |
| `git fetch <원격지>` | 원격 저장소의 변경 사항을 가져오되 **병합은 수행하지 않습니다**. |

### 자주 사용되는 예제
- `git push -u origin main`
- `git push origin main`
- `git pull origin main`
- `git fetch origin`
