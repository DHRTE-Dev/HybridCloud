## 1. 파일의 구조

리눅스 시스템의 파일은 기본적으로 세 가지 요소로 구성되어 데이터를 관리합니다.

### 주요 개념

* **파일 이름 (Filename)**: 파일에 접근하기 위해 사용되며 동일 디렉토리 내에서 유일해야 합니다. 대소문자를 구별하며, 최대 255바이트까지 생성 가능합니다. 특수문자 사용은 권장되지 않습니다.
* **I-node (Index Node)**: 파일에 대한 속성 정보와 데이터를 가리키는 포인터를 포함합니다. **파일 종류**, **퍼미션 모드**, **소유자/그룹**, **하드 링크 수**, **타임스탬프**, **파일 크기**, **데이터 블록 포인터** 정보를 담고 있으며, 고유한 번호가 할당됩니다.
* **데이터 블록 (Data Block)**: 실제 데이터가 저장되는 디스크 공간의 단위입니다. 일반 파일은 내용이, 디렉토리는 포함된 파일/디렉토리 이름이 저장되며, 디바이스 파일은 데이터를 저장하지 않고 **Major/Minor Device Number**를 저장합니다.

## 2. 파일의 종류

리눅스 시스템에서는 모든 것을 파일 형태로 다루고 관리합니다.

### 파일 종류 식별

파일 목록 확인 시 출력되는 결과의 첫 번째 문자를 통해 파일의 종류를 명확하게 식별할 수 있습니다.

| 문자 | 파일 종류 | 설명 |
|---|---|---|
| `-` | 일반 파일 (Regular File) | 텍스트, 바이너리, 이미지 등 다양한 데이터를 저장하는<br>가장 기본적인 형태의 파일입니다. |
| `d` | 디렉토리 파일 (Directory File) | 디렉토리 내부에 포함된 파일과 하위 디렉토리 정보를<br>데이터 블록에 저장하여 관리합니다. |
| `b` | 블록 디바이스 파일 (Block Device File) | 블록 단위(예: 4096 Bytes)로 입출력(I/O)이 발생하는<br>디스크 등의 스토리지 장치 파일입니다. |
| `c` | 문자 디바이스 파일 (Character Device File) | 바이트 단위로 입출력(I/O)이 발생하는<br>키보드, 콘솔 등의 장치 파일(Raw Device)입니다. |
| `l` | 심볼릭 링크 (Symbolic Link File) | 원본 파일의 위치를 가리키는 경로 정보를<br>포인트 형태로 담고 있는 바로가기 파일입니다. |
| `s` | 소켓 파일 (Socket File) | 네트워크 통신이나 프로세스 간 통신을 위해 사용됩니다. |
| `p` | 파이프 파일 (Named Pipe File) | 두 프로세스 간 데이터를 양방향으로 주고받기 위해 사용됩니다. |

## 3. 링크 파일

하나의 원본 파일을 여러 사용자가 자원을 공유하거나 관리 효율성을 높이기 위해 사용하는 파일 시스템 기능입니다.

### 링크 파일 개념

* **하드 링크 (Hard Link)**: 원본 파일과 동일한 **I-node** 번호를 공유합니다. 일반 파일에만 생성 가능하며, 디렉토리나 다른 파일 시스템에는 생성할 수 없습니다. 원본 이름이 지워져도 파일 시스템 상의 데이터는 안전하게 유지됩니다.
* **심볼릭 링크 (Symbolic Link)**: 원본 파일의 경로 정보를 담고 있는 완전히 새로운 **I-node**를 생성합니다. 디렉토리 및 다른 파일 시스템에도 제약 없이 링크 생성이 가능합니다.

### 링크 생성 명령어 옵션

| 옵션 | 설명 |
|---|---|
| `-b`, `--backup` | 대상 위치에 파일이 이미 존재할 경우<br>기존 파일을 안전하게 백업합니다. |
| `-f`, `--force` | 링크를 생성할 대상 파일이 있더라도<br>강제적으로 덮어쓰고 새로운 링크를 생성합니다. |
| `-i`, `--interactive` | 대상 파일이 이미 존재할 경우,<br>삭제 및 덮어쓰기 유무를 사용자에게 묻습니다. |
| `-n`, `--no-dereference` | 링크할 원본이 심볼릭 파일이면,<br>대상 파일을 추적하지 않고 심볼릭 파일 자체를 링크합니다. |
| `-s`, `--symbolic` | 하드 링크가 아닌 소프트 링크(심볼릭 링크)를 생성합니다. |
| `-S`, `--suffix` | 대상 파일 백업 시 지정한 확장자(suffix)를 사용하여<br>백업 파일을 명확하게 생성합니다. |

**[핵심 명령어]**
* `ln [원본 파일] [링크 파일]`: 동일한 I-node를 바라보는 **하드 링크**를 생성합니다.
* `ln -s [원본 파일] [링크 파일]`: 원본 파일의 경로를 가리키는 **심볼릭 링크**를 생성합니다.

## 4. 하드웨어 및 시스템 정보

### 디바이스 파일 개념

장치를 제어하기 위한 인터페이스 역할을 하며 데이터를 직접 저장하지 않습니다.
* **Major Device Number**: 해당 장치의 대분류 종류를 식별합니다.
* **Minor Device Number**: 같은 종류 내에서 개별 장치나 고유한 동작 방식을 식별합니다.

### 하드웨어 정보 확인 명령어

| 명령어 | 설명 |
|---|---|
| `lscpu` | CPU 아키텍처, 코어 수, 벤더, 캐시 크기 등<br>**상세한 CPU 사양**을 출력합니다. |
| `lsmem` | 시스템에 장착된 전체 **메모리(RAM) 용량 및 가용 상태**를 확인합니다. |
| `lsscsi` | CD/DVD-ROM, 하드 디스크 등 **SCSI 기반 장치 목록**을 확인합니다. |
| `lspci` | 메인보드에 연결된 **PCI 버스 및 장착된 디바이스 정보**를 확인합니다. |
| `lsusb` | 시스템에 연결된 **USB 컨트롤러 및 외부 USB 장치 목록**을 확인합니다. |
| `lshw` | 시스템에 구성된 **전체적인 하드웨어 상세 정보**를 출력합니다. |
| `hardinfo` | 벤치마크 테스트 및 종합적인 하드웨어 시스템 정보를<br>직관적인 GUI 환경에서 제공합니다. |

**[핵심 명령어]**
* `lsblk`: 시스템에 인식된 전체 **블록 디바이스(디스크, 파티션 등)** 구조를 한눈에 트리 형태로 확인합니다.
* `lscpu`: 시스템의 **CPU 핵심 아키텍처 정보**를 요약하여 보여주는 가장 기본적인 점검 명령어입니다.
