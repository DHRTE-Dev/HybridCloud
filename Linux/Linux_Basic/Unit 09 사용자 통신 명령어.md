## 1. mail / mailx 명령어

### 개념 및 패키지 설정
- **개념**: 리눅스/유닉스 환경에서 전자 우편을 송수신하기 위해 사용하는 기본 통신 명령어입니다. **System V** 계열에서는 **mailx**, **BSD** 계열 및 **CentOS/RHEL** 환경에서는 **mail** 명령어를 사용합니다.
- **주요 패키지 및 서비스**:

| 구분 | 패키지/프로그램명 | 설명 |
| --- | --- | --- |
| **Mail Server (MTA)** | **Postfix** | CentOS 7 이상 기본 메일 서버 프로그램<br>(CentOS 6 이하 버전에서는 **Sendmail** 사용) |
| **Mail Client (MUA)** | **s-nail** / **mailx** | 메일 송수신 인터페이스를 제공하는 클라이언트 프로그램 |
| **서비스 기동 명령어** | `systemctl enable --now postfix` | **Postfix** 서비스를 자동 실행 등록하고 즉시 기동 |

---

### 명령어 옵션 및 수신 메일 상태
- **mail 명령어 주요 옵션**:

| 옵션 | 설명 |
| --- | --- |
| `-s "제목"` | 메일 발신 시 제목(**Subject**)을 지정 |
| `-u 사용자ID` | 특정 사용자의 수신 메일함을 확인<br>(**root** 관리자 권한 필수) |
| `-v` | 메일 전송 상세 처리 과정(**Verbose mode**)을 터미널에 출력 |
| `-f [파일명]` | 기본 수신함 대신 지정한 메일 저장 파일을 열어서 확인 |
| `-c 주소` | 참조(**CC**) 수신자 지정 |
| `-b 주소` | 숨은 참조(**BCC**) 수신자 지정 |

- **수신 메일 목록 출력 항목 및 상태 코드**:

| 구성 요소 | 예시 출력 | 설명 |
| --- | --- | --- |
| **메일 상태 코드** | `>N` | `N`: 읽지 않은 신규 메일 (**New**)<br>`U`: 읽지 않은 이전 메일 (**Unread**)<br>` `(공백): 이미 확인한 읽은 메일 |
| **메일 ID** | `1` | 수신함 내 메일의 고유 식별 번호 |
| **발신자** | `root` | 메일을 발송한 사용자 계정 (**From**) |
| **전송 일시** | `Fri Feb 19 15:20` | 메일이 수신된 날짜 및 시간 |
| **메일 용량** | `22/857` | 메일 본문의 줄 수 / 바이트(**Byte**) 크기 |
| **메일 제목** | `"test mail"` | 전송 시 입력된 메일 제목 (**Subject**) |

---

### mail / mailx 사용 예제
- **자주 사용되는 주요 명령 예제**:

| 작업 구분 | 실행 명령 | 설명 |
| --- | --- | --- |
| **수신 메일 확인** | `mail` | 현재 로그인한 사용자의 수신 메일함 열기 |
| **타 계정 메일 읽기** | `mail -u user01` | **root** 권한으로 **user01** 사용자의 수신함 열기 |
| **대화형 메일 전송** | `mail user01` | 본문 작성 후 `<Ctrl + D>` 또는 `.` 입력하여 전송 |
| **제목 지정 전송** | `mail -s "Test Mail" user01` | 제목을 미리 지정하여 특정 사용자에게 메일 발송 |
| **파일 본문 전송** | `mail -s "Report" admin@example.com < report.txt` | `report.txt` 파일 내용을 본문으로 첨부하여 즉시 발송 |
| **다중 사용자 전송** | `for u in $(cat email.list); do mail -s "Notice" $u < /etc/hosts; done` | 메일 목록 파일(`email.list`)을 순회하며 일괄 전송 |

## 2. wall 및 사용자 통신 명령어

### 개념 및 메시지 관련 명령어 비교
- **개념**: **wall** (**Write All**) 명령어는 현재 시스템에 접속(로그인)되어 있는 모든 사용자의 터미널 화면으로 메시지를 즉시 브로드캐스트 전송하는 관리자/사용자 통신 명령어입니다.
- **사용자 통신 관련 명령어 비교**:

| 명령어 | 전송 대상 | 권한 및 수신 거부 | 주요 용도 및 특징 |
| --- | --- | --- | --- |
| **wall** | 전체 접속 사용자 | **root**는 수신 거부 설정 무시 | 시스템 점검, 긴급 재부팅 등 전체 공지 메시지 전송 |
| **write** | 특정 사용자 (tty/pts) | 상대방의 수신 허용 필요 | 특정 터미널 사용자와 1:1 대화 메시지 전송<br>종료 시 `<Ctrl + D>` 입력 |
| **mesg** | 단일 사용자 자신 | 본인 계정 전용 | 터미널 메시지 수신 허용(`mesg y`) 및 거부(`mesg n`) 설정 |

---

### wall 명령어 옵션 및 긴급 작업 제어
- **wall 명령어 주요 옵션**:

| 옵션 | 설명 |
| --- | --- |
| `-n` | 메시지 전송 시 기본 출력되는 상단 배너(**Header**) 표시를 억제 |
| `-t 초` | 메시지 전송 시 타임아웃 시간 지정 |
| `-g 그룹명` | 특정 그룹에 속한 접속 사용자의 터미널로만 메시지 제한 전송 |

- **긴급 작업 시 관련 제어 파일 및 명령어**:

| 구분 | 명령어 / 파일 경로 | 역할 및 설명 |
| --- | --- | --- |
| **원격 접속 차단** | `/etc/nologin` | 파일 생성 시 일반 사용자의 신규 원격 로그인(SSH/Telnet) 전면 차단<br>(**root** 계정만 접속 허용, 작업 종료 후 파일 삭제 필수) |
| **점유 프로세스 확인** | `fuser -cu /home` | 특정 디렉토리/파일시스템을 점유 중인 사용자 및 **PID** 확인 |
| **점유 프로세스 강제 종료** | `fuser -ck /home` | 특정 디렉토리를 사용 중인 모든 프로세스에 **SIGKILL** 전송 |

---

### wall 및 긴급 작업 사용 예제
- **자주 사용되는 주요 명령 및 긴급 작업 절차 예제**:

| 작업 단계 | 실행 명령 | 설명 |
| --- | --- | --- |
| **단문 공지 전송** | `wall "Start working on /home after 30 minutes."` | 접속 중인 모든 사용자 화면에 긴급 메시지 출력 |
| **파일 내용 공지** | `wall < /etc/MESS/work.txt` | 사전 작성된 공지문 파일(`work.txt`) 내용을 전체 전송 |
| **신규 접속 차단** | `touch /etc/nologin` | 파일시스템 점검 등 긴급 작업 전 일반 사용자 접속 차단 |
| **점유 프로세스 정리** | `fuser -cu /home`<br>`fuser -ck /home` | `/home` 디렉토리 사용자를 확인하고 프로세스 강제 종료 |
| **접속 차단 해제** | `rm -f /etc/nologin` | 작업 완료 후 `/etc/nologin` 파일을 삭제하여 정상 로그인 허용 |
