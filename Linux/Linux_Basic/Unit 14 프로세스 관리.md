## 1. 프로세스 정보

### 프로세스의 개념 및 상태
* **프로세서(Processor)**: 컴퓨터의 중앙 처리 장치(**CPU**)를 의미합니다.
* **프로세스(Process)**: 디스크에 보관되어 있던 프로그램이 메모리(**RAM**)에 적재되어 실제로 실행되고 있는 상태 또는 실행 인스턴스를 의미합니다.
* **프로세스의 주요 구성 및 특징**:
  * 프로그램이 실행될 때 하나 이상의 프로세스를 생성합니다.
  * 할당된 **가상 주소 공간(Virtual Address Space)**, **보안 등록 정보**(소유권 및 권한), 하나 이상의 실행 **스레드(Thread)**, CPU 레지스터, 데이터 스택, 할당된 시스템 리소스(파일 설명자, 네트워크 포트 등)로 구성됩니다.
  * 개별 프로세스는 고유의 가상 주소 공간에서 실행되며 커널이 제공하는 **IPC(Inter-Process Communication)** 인터페이스를 통해서만 타 프로세스와 연동합니다.
  * 오류 발생 시 독립된 주소 공간 덕분에 다른 프로세스에 직접적인 영향을 주지 않고 시스템 격리가 유지됩니다.
* **프로세스 라이프 사이클(Life Cycle)**:
  * **fork**: 부모 프로세스가 자신의 복제본인 자식 프로세스를 생성합니다.
  * **exec**: 자식 프로세스가 새로운 프로그램 코드를 메모리에 올려 주소 공간을 교체 실행합니다.
  * **exit**: 프로세스가 실행을 완료하고 종료 코드를 커널에 전달하며 종료합니다.
  * **zombie**: 프로세스 실행은 종료되었으나 부모 프로세스가 종료 상태를 수거하지 않아 커널 프로세스 테이블에 남아 있는 상태입니다.
* **프로세스 상태 플래그 및 커널 정의**:

| 상태 플래그 | 커널 상태 이름 | 설명 |
| :--- | :--- | :--- |
| **R** | TASK_RUNNING | 프로세스가 CPU에서 실행 중이거나 실행을 기다리는 실행 가능(Runnable) 상태입니다. |
| **S** | TASK_INTERRUPTIBLE | 이벤트, 신호, 하드웨어 요청 등을 대기하는 수면(Sleeping) 상태입니다. 조건을 만족하면 Running 상태로 복귀합니다. |
| **D** | TASK_UNINTERRUPTIBLE | 디스크 I/O 등 신호에 응답하지 않는 불인터럽트 수면 상태입니다. 예기치 않은 장치 상태 변화를 방지할 때 사용됩니다. |
| **K** | TASK_KILLABLE | D 상태와 동일하지만 치명적인 강제 종료 신호(SIGKILL)에 응답할 수 있도록 수정된 상태입니다. |
| **I** | TASK_REPORT_IDLE | 커널 스레드 전용 D 상태의 하위 집합입니다. 시스템 부하 평균(Load Average) 계산 시 제외됩니다. |
| **T** | TASK_STOPPED | 사용자 또는 프로세스의 신호(SIGSTOP, SIGTSTP)를 받아 작업이 일시 중지된 상태입니다. |
| **T** | TASK_TRACED | 디버깅(Debug) 수행으로 인해 일시적으로 중지된 상태입니다. |
| **Z** | Zombie | execution이 완료되어 종료되었으나 부모 프로세스에 의해 수거되지 않은 **좀비 프로세스** 상태입니다. |

### 부모 및 자식 프로세스
* **PID (Process Identification)**: 프로세스가 생성될 때 커널로부터 할당받는 고유 식별 번호입니다.
* **PPID (Parent Process Identification)**: 해당 프로세스를 실행시킨 부모 프로세스의 식별 번호입니다.
* **부모 및 자식 프로세스 간의 관계**:
  * 자식 프로세스(서브 프로세스)는 부모 프로세스의 자원 일부를 공유합니다.
  * 부모 프로세스가 종료되면 자식 프로세스는 스스로 존재할 수 없으며, 부모가 먼저 종료될 경우 systemd(PID 1) 프로세스로 재배정(고아 프로세스 수거)됩니다.

### 데몬 프로세스
* **데몬(Daemon)**: 시스템 백그라운드에서 상주하며 특정 서비스나 네트워크 요청을 처리하기 위해 동작하는 프로세스입니다.
* **특징**:
  * 커널상에서 백그라운드 모드로 작동하여 비활성화 상태에서는 CPU 부하를 거의 주지 않습니다.
  * 수신 요청을 대기하기 위해 지속적으로 메모리 공간을 점유하므로 과도한 데몬 실행은 메모리 자원을 소비시킵니다.
* **주요 데몬 종류**:
  * 웹 데몬: **httpd**
  * 메일 데몬: **sendmail**
  * FTP 데몬: **vsftpd**
  * Telnet 데몬: **telnetd**

### /proc 디렉토리
* **`/proc` 디렉토리**: 커널 메모리를 파일 시스템 형태로 마운트한 Virtual File System 디렉토리입니다.
* **특징 및 구조**:
  * 실행 중인 각 프로세스의 **PID** 번호에 해당하는 디렉토리(`/proc/PID`)가 실시간으로 생성됩니다.
  * `/proc/PID` 내부에는 프로세스의 실행 명령, 메모리 맵, 환경 변수, 파일 서술자 등 커널이 관리하는 세부 정보가 저장되어 있습니다.
  * 프로세스가 종료되면 해당 `/proc/PID` 디렉토리는 자동으로 삭제됩니다.

## 2. 프로세스 관리

### 포그라운드 및 백그라운드 관리
* **포그라운드(Foreground) 실행**:
  * 쉘 프롬프트에서 일반적인 방식으로 명령어를 실행하여 표준 입출력 및 터미널 제어권을 점유합니다.
  * 프로세스가 종료되기 전까지 쉘 프롬프트를 다시 사용할 수 없습니다.
* **백그라운드(Background) 실행**:
  * 명령어 뒤에 **`&`** (앰퍼샌드) 기호를 붙여 실행합니다.
  * 터미널 제어권을 즉시 사용자에게 반환하므로 프로세스가 뒤에서 실행되는 동안 쉘 프롬프트에서 다른 작업을 수행할 수 있습니다.
* **잡(Job) 제어 명령어 및 단축키**:

| 구분 / 명령어 | 설명 |
| :--- | :--- |
| **명령어 &** | 프로세스를 백그라운드 모드로 실행 |
| **jobs** | 현재 터미널에서 관리 중인 백그라운드/일시중지 작업 목록 및 작업 번호(Job ID) 출력 |
| **fg %작업번호** | 지정한 작업 번호의 프로세스를 포그라운드로 전환 |
| **bg %작업번호** | 일시 중지(Stopped) 상태의 작업을 백그라운드 실행(Running) 상태로 전환 |
| **kill %작업번호** | 작업 번호에 해당하는 백그라운드 작업 종료 |
| **Ctrl + Z** | 포그라운드 프로세스를 일시 중지(Stopped)하고 백그라운드로 전환 |
| **Ctrl + C** | 포그라운드 프로세스에 인터럽트 신호를 보내 실행 중단 및 강제 종료 |

### 자주 사용되는 예제
* 백업 스크립트 백그라운드 실행: /root/bin/backup.sh &
* GUI 프로그램 백그라운드 실행: gedit & 또는 firefox &
* 작업 중인 포그라운드 프로세스를 백그라운드로 전환: 실행 중 Ctrl + Z 입력 후 bg %1 실행
* 백그라운드 1번 작업을 포그라운드로 전환: fg %1
* 백그라운드 2번 작업 종료: kill %2

### 프로세스 상태 조회
* **`ps` 명령어**: 시스템에서 실행 중인 프로세스의 상태 정보를 확인하는 스냅샷 도구입니다.
* **표준 옵션 스타일 구분**:
  * **System V (UNIX) 스타일**: `-ef`와 같이 대시(`-`)를 사용하는 옵션입니다.
  * **BSD 스타일**: `aux`와 같이 대시(`-`) 없이 사용하는 옵션입니다.
* **`ps` 주요 옵션**:

| 옵션 | 스타일 | 설명 |
| :--- | :--- | :--- |
| **-e** | System V | 시스템 내 모든 프로세스 리스트 출력 |
| **-f** | System V | 풀 포맷(Full Format)으로 상세 정보(UID, PID, PPID, STIME, TTY 등) 출력 |
| **-u <사용자>** | System V | 지정한 유효 사용자 ID/이름에 해당하는 프로세스 출력 |
| **-U <사용자>** | System V | 지정한 실제 사용자 ID/이름에 해당하는 프로세스 출력 |
| **-t <터미널>** | System V | 지정한 터미널(TTY)에 연관된 프로세스 출력 |
| **-p <PID>** | System V | 지정한 PID 식별 번호의 프로세스 출력 |
| **a** | BSD | 다른 사용자의 프로세스를 포함하여 터미널이 할당된 모든 프로세스 출력 |
| **u** | BSD | 프로세스 소유자, CPU %, 메모리 %, VSZ, RSS 등 사용량 위주의 상세 정보 출력 |
| **x** | BSD | 제어 터미널(TTY)이 없는 프로세스(데몬 프로세스 등)까지 모두 출력 |

* **`ps aux` 주요 필드 및 STAT 상태 코드**:

| 필드 / 코드 | 설명 |
| :--- | :--- |
| **USER / UID** | 프로세스를 소유하고 실행한 사용자 계정 |
| **PID / PPID** | 프로세스 ID 및 부모 프로세스 ID |
| **%CPU / %MEM** | 프로세스가 사용 중인 CPU 및 물리 메모리 점유율 |
| **VSZ** | 가상 메모리 크기 (KB 단위) |
| **RSS** | 실제 물리 메모리에 적재된 상주 크기 (Resident Set Size, KB 단위) |
| **STAT** | 프로세스의 현재 상태 코드<br>- **R**: 실행 중 (Running)<br>- **S**: 인터럽트 가능한 수면 (Sleep)<br>- **D**: 인터럽트 불가능 수면 (Disk I/O 대기)<br>- **T**: 일시 정지 (Stopped)<br>- **Z**: 좀비 프로세스 (Zombie)<br>- **s**: 세션 리더 프로세스<br>- **+**: 포그라운드 프로세스 그룹<br>- **<**: 높은 우선순위<br>- **N**: 낮은 우선순위 |

### 자주 사용되는 예제
* 전체 프로세스 리스트 풀 포맷 상세 조회: ps -ef | less
* 데몬 포함 전체 프로세스 사용량 상세 조회: ps aux | grep rsyslogd
* root 사용자가 실행 중인 프로세스 조회: ps -U root
* 특정 터미널(pts/3) 프로세스 조회: ps -t pts/3

### 좀비 프로세스
* **개념**: 프로세스가 execution을 완료하고 종료(`exit`)되었으나 부모 프로세스가 종료 상태(`exit status`)를 수거(`wait`)하지 않아 커널 프로세스 테이블에 남은 상태(`<defunct>`)입니다.
* **특징**: CPU나 메모리 자원은 사용하지 않으나, PID 및 프로세스 테이블 항목을 점유하므로 과도할 경우 PID 고갈을 유발할 수 있습니다.
* **확인 명령**:
  * `ps -ef | grep defunct`
  * `ps -elf | awk '$2=="Z" {print $0}'`
* **조치**: 부모 프로세스에 종료 신호를 보내 수거하도록 하거나, 부모 프로세스를 종료하여 systemd(PID 1)가 수거하도록 조치합니다.

### 프로세스 종료 및 시그널
* **시그널(Signal)**: 커널 또는 프로세스가 다른 프로세스에게 비동기적으로 이벤트를 알리기 위해 전송하는 메세지입니다.
* **주요 시그널 번호 및 명칭**:

| 시그널 번호 | 시그널 이름 | 설명 |
| :--- | :--- | :--- |
| **1** | **SIGHUP** | Hangup. 프로세스 재시작 및 종료 없이 설정 파일 재로드(Reload) 시 사용됩니다. |
| **2** | **SIGINT** | Interrupt. 키보드 인터럽트(Ctrl + C). 프로그램을 정중하게 종료합니다. |
| **3** | **SIGQUIT** | Quit. 키보드 종료(Ctrl + \). 프로세스 덤프(Core Dump)를 생성하고 종료합니다. |
| **9** | **SIGKILL** | Kill. 강제 종료 신호. 프로세스가 무시, 차단, 포착할 수 없으며 커널이 즉시 프로세스를 강제 종료합니다. |
| **15** | **SIGTERM** | Terminate. 정상 종료 신호(kill 명령의 기본값). 프로세스가 정리 작업을 수행하고 종료할 수 있도록 요청합니다. |
| **18** | **SIGCONT** | Continue. 정지(Stopped) 상태에 있는 프로세스를 다시 실행 재개합니다. |
| **19** | **SIGSTOP** | Stop. 프로세스 일시 중지. 프로세스가 차단하거나 무시할 수 없습니다. |
| **20** | **SIGTSTP** | Terminal Stop. 키보드 일시 중지(Ctrl + Z). 프로세스가 차단 또는 무시할 수 있습니다. |

* **종료 명령어**:

| 명령어 | 설명 |
| :--- | :--- |
| **kill [시그널] PID** | 지정한 PID 프로세스에 해당 시그널을 전달하여 종료 |
| **killall [시그널] 프로세스명** | 지정한 이름을 가진 모든 프로세스에 시그널을 전달하여 일괄 종료 |
| **pkill [시그널] 패턴** | 프로세스 이름 패턴을 조건으로 검색하여 일괄 시그널 전송 및 종료 |

### 자주 사용되는 예제
* PID 46340 프로세스 정상 종료 요청: kill 46340 또는 kill -15 46340
* PID 46468 프로세스 강제 종료: kill -9 46468
* httpd 데몬 전체 일괄 종료: killall httpd 또는 pkill httpd
* 프로세스 설정 파일 재로드: kill -1 450

## 3. 프로세스 모니터링

### top 명령어를 통한 실시간 모니터링
* **`top` 명령어**: 시스템의 리소스(CPU, 메모리, Swap) 사용량 및 프로세스 상태를 실시간으로 모니터링하는 TUI 기반의 도구입니다.
* **기본 동작**: 화면 갱신 간격(Delay)은 기본 3.0초이며, **%CPU** 사용량을 기준으로 내림차순 정렬하여 출력합니다.
* **상단 헤더 정보 해석**:
  * **1행 (uptime 및 부하량)**: 시스템 현재 시간, 부팅 후 운영 시간, 접속 사용자 수, **Load Average**(1분, 5분, 15분 동안의 평균 프로세스 부하량).
  * **2행 (Tasks)**: 전체 프로세스 수, Running, Sleeping, Stopped, Zombie 프로세스 수.
  * **3행 (%Cpu(s))**: `us`(사용자 공간), `sy`(커널 공간), `ni`(Nice 점수), `id`(대기/Idle), `wa`(I/O 대기), `hi`(하드웨어 인터럽트), `si`(소프트웨어 인터럽트), `st`(가상화 Steal Time).
  * **4/5행 (Mem 및 Swap)**: 전체, 여유, 사용 중, Buff/Cache 물리 메모리 및 Swap 메모리 현황.
* **`top` 대화형 단축키**:

| 단축키 | 설명 |
| :--- | :--- |
| **h** 또는 **?** | 대화형 입력 명령어 도움말 화면 출력 |
| **l** | 상단 부하량(Load Average) 헤더 라인 표시/숨김 토글 |
| **t** | 프로세스 및 CPU 상태 헤더 라인 표시 방식 변경 토글 |
| **m** | 메모리 및 스왑 헤더 라인 표시 방식 변경 토글 |
| **1 (숫자 1)** | 개별 CPU 코어별 사용량 / 전체 CPU 요약 표시 토글 |
| **s** | 화면 갱신 주기(Delay Time) 변경 (예: 5.0, 10.0 입력) |
| **u** / **U** | 지정한 사용자(Effective / Real User)의 프로세스만 필터링 출력 |
| **P (Shift + p)** | **CPU 사용량**을 기준으로 프로세스 목록 내림차순 정렬 |
| **M (Shift + m)** | **메모리 사용량**을 기준으로 프로세스 목록 내림차순 정렬 |
| **k** | 프로세스 종료 대화창 호출 (PID 입력 후 Signal 번호 입력) |
| **r** | 프로세스 우선순위(Nice Value) 변경 대화창 호출 |
| **W (Shift + w)** | 현재 top 대화형 정렬/설정 상태를 파일(`~/.config/procps/toprc`)에 저장 |
| **f** | 표시 열 관리 및 정렬 필드(Sort Field) 변경 화면 이동 |
| **q** | top 프로그램 종료 |

### 자주 사용되는 예제
* fedora 사용자의 프로세스만 실시간 모니터링: top -u fedora
* 특정 PID(1234, 5678) 프로세스만 지정 모니터링: top -p 1234,5678
* top 실행 중 CPU 사용량 순 정렬: P 키 입력
* top 실행 중 메모리 사용량 순 정렬: M 키 입력
* top 실행 중 특정 프로세스 종료: k 키 입력 후 PID 및 시그널 번호(9) 입력

### 기타 시스템 모니터링 툴
* 다양한 리소스(CPU, 메모리, 디스크 I/O, 네트워크 I/O) 모니터링 도구 비교:

| 툴 이름 | 주요 모니터링 리소스 | 특징 및 설명 |
| :--- | :--- | :--- |
| **top** | CPU, 메모리, 프로세스 | 기본 제공 표준 실시간 모니터링 툴 |
| **htop** | CPU, 메모리, 프로세스 | 대화형 컬러 UI, 마우스 클릭 지원, 프로세스 트리 뷰 제공 (EPEL 필요) |
| **iotop** | 디스크 I/O | 프로세스별 디스크 읽기/쓰기 속도를 실시간 측정 |
| **iftop** | 네트워크 I/O | 네트워크 인터페이스별 대역폭 사용량 및 호스트 간 트래픽 모니터링 (EPEL 필요) |
| **bmon** | 네트워크 I/O | 네트워크 대역폭 모니터링 및 실시간 비주얼 그래프 출력 (EPEL 필요) |
| **atop** | CPU, 메모리, 디스크, 네트워크 | 종합 시스템 성능 모니터링 툴. 데이터 수집 서비스(`atop.service`) 및 로그 기록 분석 지원 |
| **btop** | 종합 리소스 | 세련된 TUI 그래픽 패널 기반 종합 리소스 모니터링 툴 (EPEL 필요) |

* **EPEL 리포지토리 및 패키지 설치 준비**:
  * EPEL 패키지 저장소 등록: dnf -y install epel-release
  * 모니터링 패키지 일괄 설치: dnf -y install htop iftop atop iotop btop bmon
